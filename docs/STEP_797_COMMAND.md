## 수정

### 1) 🔴 공시 "0건" vs "못 가져옴" 구분 — 거짓 사실 주장 제거 (최우선)

**문제**: 795에서 공시 0건 카드("최근 중대한 사건은 없어요")를 도입했는데, 5개국 공시 API가 **상류 실패·미매핑까지 200 + 빈 배열로 삼킴** → 장애 상황에서 "사건이 없다"고 단언하게 됨(3기둥 §직시 위반). 클라의 `!r.ok` 분기는 사실상 절대 안 걸림.

- 실패 삼킴 위치: `app/api/kr-events/route.ts`(`.catch(() => [])`) · `gb-events`·`cn-events`·`vn-events`(`catch { }` graceful) · `jp-events`(`if (!error && data)` 실패 시 빈 배열).
- 미매핑도 동일: `gb`(tidm 없음) · `jp`(sec 없음) · `vn`(ticker 없음) · `cn`(p 없음)이 전부 200 빈 배열.

**조치 — 세 상태를 구분해 반환**:
- `ok`(0건 포함) → `{ events: [...] }`
- `fetch_failed`(상류 장애·타임아웃) → `{ events: [], error: 'fetch_failed' }`
- `unsupported`(심볼 매핑 없음) → `{ events: [], error: 'unsupported' }`

**클라(`StockLensClient.tsx` 5개 층 + 공용 `FilingsCard`)**:
- `ok` + 0건 → **"최근 중대한 사건은 없어요" 카드**(현행 문구)
- `fetch_failed` → **섹션 숨김**(795 이전 동작 — 지어내지 않음)
- `unsupported` → 숨김(또는 "이 시장은 공시 연동 준비 중" — 기존 결측 문법이 있으면 재사용, 없으면 숨김)
- **0건일 때 `noticeNode`("렌즈 점수엔 아직 안 반영된 최신 공시예요") 출력 금지** — 공시가 있다는 전제라 모순. 0건 전용 표시만.
- API 주석의 "못 가져오면 빈 층(숨김)"도 새 계약으로 갱신.

### 2) 🔴 GB 캐시 포이즈닝 봉인 (793 잔존 구멍)

- `app/api/gb-events/summary/route.ts` — 캐시 키가 URL 끝 숫자(`"GB"+id`)인데 허용 정규식 중간 세그먼트가 `[^?#"']+`라 **`/`·`..` 통과**. 실증: `.../rns/a/../../../company/BP./9123456` → 정규화되어 investegate 내 임의 페이지 본문을 임의 GB id로 저장 가능.
- 조치: **CN/VN과 동일하게 `acc = "GB" + sha1(url).slice(0,24)`** + 중간 세그먼트를 `[A-Za-z0-9._-]+`로 제한하고 `..` 명시 거부. (CN/VN/GB 키 파생 로직은 **공용 헬퍼 1개**로 통일 권장.)
- 6개국 요약 라우트를 나란히 재점검해 같은 종류의 여지가 더 없는지 확인 후 보고.

### 3) `lib/rateLimit.ts` — sweep이 증폭기 되는 문제

- 현재: `map.size < 5000`이면 return, 초과 시 **매 요청마다 두 맵 전체 순회**. 만료 항목이 없으면 비용만 O(n)으로 계속 증가(분산 요청 시 CPU·메모리 동시 상승).
- 조치: **마지막 sweep 시각 기준 주기 실행**(예: 60초에 1회) + **하드 상한**(초과 시 오래된 항목부터 제거). 상한 도달 시 조용히 실패하지 말고 카운터 증가.
- 시간 버킷이 거부해도 분 버킷을 소비하는 순서 문제도 정리(거부 시 롤백 또는 검사 순서 변경).
- **관측성**: 차단 발생 시 최소한의 로깅(카운터 + 주기적 Sentry breadcrumb/메시지 1건) — 베타에서 "요약이 안 떠요" 신고가 오면 게이트 탓인지 판별 가능해야 함. **IP는 로그에 남기지 말 것**(개인정보).
- 클라이언트 IP는 `x-forwarded-for` 첫 요소 대신 Vercel 신뢰 헤더 사용 검토.

### 4) 렌즈 Sentry 폭주 억제

- `lib/lensCompute.ts`의 per-lens 실패 캡처가 **렌즈×심볼 단위** → `lib/lensPrecompute.ts`가 전 유니버스(수천 종목)를 돌 때 한 렌즈가 구조적으로 실패하면 크론 1회에 수천~수만 건 캡처(쿼터 소진·알림 매몰).
- 조치: **실행 컨텍스트당 렌즈키별 1회만 캡처**(모듈 스코프 Set 또는 배치 플래그) + 실패 건수는 집계해 마지막에 1건으로 요약 보고.
- 부수 확인: 이제 렌즈 1개 실패 시 `lens_scores`에 **그 렌즈만 null인 부분 행**이 저장됨(이전엔 심볼 통째 스킵). 탐색 랭킹이 조용히 그 렌즈를 잃으므로, **부분 저장이 맞는지 판단**해 (a) 그대로 두되 집계 로그로 감시 (b) 특정 렌즈 실패율이 임계 초과면 저장 스킵 중 택1하고 사유를 보고.

### 5) 브리핑 실패도 공시와 같은 톤으로

- `StockLensClient.tsx`의 종목 브리핑이 실패 시 `return null`(무음) → **같은 화면에서 공시는 "없어요"라 말하고 브리핑은 말없이 사라지는** 정책 불일치.
- 조치: 브리핑 실패 시 공시와 동일한 결측 문법으로 1줄 표시(문구는 기존 결측 어휘 재사용·새 문구 발명 금지). 데이터 자체가 없는 경우(생성 전)와 실패를 구분할 수 있으면 구분.
