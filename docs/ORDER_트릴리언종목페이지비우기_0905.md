# ORDER — Trillion 종목 페이지 비우기 (2026-09-05)

방향 전환(2026-09-05 확정, ROADMAP_V2 「방향 전환」절)의 첫 실행 STEP.
종목 페이지에서 **모델 화면 요소를 걷어내** 리포트가 들어올 빈 그릇으로
만든다. 유입 없는 사이트이므로 빈 화면 노출은 문제 삼지 않는다.

## 이 STEP의 범위 — 화면만
- **건드리는 것**: 종목 상세 페이지(app/[locale]/stock/[symbol]/ 및 그
  하위 클라이언트 컴포넌트)에서 모델 산출 UI 제거/숨김
- **건드리지 않는 것(이번 STEP 아님)**: 크론(vercel.json), 모델 계산
  파이프라인(lib/lenses·revdcf 등), Supabase 모델 테이블, /api 라우트의
  계산 로직. 이건 리포트 적재까지 끝난 뒤 별도 STEP에서 정리한다.
- 한 STEP = 한 종류 변경(화면). 크론까지 같이 내리지 않는 이유는 사고
  시 원인 추적을 위해서다.

deploy-gates.md 준수: 프로덕션 배포는 push 후 CI verify + Vercel Ready
확인까지가 완료. Public 저장소이므로 비밀 금지.

## STEP 1 — 조사·계획 (보고 후 대기)
종목 상세 페이지를 열어, 화면에 렌더되는 요소를 **모델 산출물 / 유지
UI**로 분류해 표로 보고한다(추측 금지, 컴포넌트·줄번호 좌표).
- 예상 모델 요소: 압축 렌즈 헤더, TR-AI 7렌즈 카드(모멘텀·저변동·밸류·
  퀄리티·자산성장·기술·F스코어), 역DCF 섹션(RevDcfSection·이미 플래그
  OFF), 배수 카드, AI 브리핑(R2), 공시요약(R1), 뉴스 — 각각이 "모델
  계산 결과인가 / 리포트로 대체될 것인가 / 종목 페이지에 남을 UI인가"
- 유지 후보(리포트 플랫폼에도 필요할 수 있는 것): 현재가·로고·종목명·
  국가·언어 토글·헤더·티커·관심종목 버튼 — 이들이 모델과 분리돼 있는지,
  얽혀 있으면 어디서 얽히는지
- 제거 방식 선택지와 트레이드오프: (a)컴포넌트를 조건부로 안 그리게
  (b)피처 플래그로 숨김 (c)파일 자체를 파킹 — 되돌리기 쉬움·사고
  위험·깔끔함 기준으로 각 요소에 무엇이 맞는지 제안
- 데이터 계약 주의: 모델 요소를 지우면 그 요소가 호출하던 /api 라우트가
  고아가 되는데, 라우트 자체는 이번에 안 지우고 **화면 호출만** 끊는지
  확인(라우트 삭제는 다음 STEP)

## STEP 2 — 확정 후 실행
STEP 1 계획 승인 후:
- 종목 페이지에서 모델 요소 제거/숨김(승인된 방식대로)
- 페이지가 "종목 기본정보(현재가·로고·이름) + 리포트 자리(플레이스홀더
  '리포트 준비 중' 또는 빈 섹션)"만 남도록
- 제거한 것/남긴 것/고아가 된(그러나 살려둔) 라우트 목록을 보고
- 라이브에서 종목 페이지가 에러 없이 뜨는지 확인(빈 상태 OK, 500 불가)
- 커밋·push, 게이트 8(CI verify + Vercel Ready) 확인
