2. 운영 방식 — Cowork·Claude Code 역할과 STEP 체계

2-1. 역할 분담 (절대 혼용 금지)

Cowork (클로드 채팅 / 이 앱)Claude Code (터미널 CLI)
별명두뇌 — 설계·작성손 — 실행·빌드
하는 일사용자와 대화하며 무엇을 만들지 결정 · 명령어/코드/설정 직접 작성 · 문서 갱신 · Supabase MCP로 DB 조회/마이그레이션 적용Cowork이 만든 명령어를 실제 실행 · 파일 수정 · npm/빌드 · git commit/push · 서버 재시작
하지 않는 일실행하지 않음 (빌드·push 안 함)설계 결정 안 함

작업 흐름: 사용자가 Cowork에게 원하는 것 말하기 → Cowork이 명령어/코드 작성 → 사용자가 Claude Code 터미널에 붙여넣어 실행 → 결과를 Cowork에게 공유 → 다음 단계.

2-2. STEP 체계 (작업 단위)

  • 모든 작업은 STEP 번호(연속)로 관리한다. 2026-09-05 기준 STEP 1090+까지 진행됨.
  • 명령서 파일 방식: 3단계 이상 작업이면 docs/STEP_{번호}_COMMAND.md로 저장하고, Claude Code에서 @docs/STEP_N_COMMAND.md 파일 내용대로 실행해줘로 호출. 실행 후 파일은 삭제하지 않고 보존(아카이브 역할).
  • 인라인 방식: 1~2파일 수정·10줄 이내면 채팅 코드블록으로. 한 블록 = 한 번의 붙여넣기(설명과 분리한 단독 코드블록).
  • 모델 선택: 기본 Sonnet(cd ~/stock-terminal && claude --dangerously-skip-permissions --model sonnet). Cowork이 🔴 Opus 권장 배지를 붙인 경우만 Opus(원인 불명 에러 디버깅·대규모 리팩토링·복잡 알고리즘·레거시 해독).
  • 기록 의무: STEP 하나당 docs/STEP_LEDGER.md에 한 줄(✅성공/🟡부분/🔴실패/⬜미실행 — 성공도, 미실행도 기록). 문제·교훈이 생기면 docs/LENS_DEV_PLAYBOOK.md에 즉시 한 행. 몰아서 기록 금지 — 결과를 보는 그 자리에서.
  • "로그 없으면 미완료" — 빌드가 성공해도 기록이 없으면 미완료로 취급한다.

2-3. 판단 규칙 (Cowork이 지켜야 하는 것)

  • 3중 규칙: 결론 전에 ①3번 검색(원전·실무·반대증거, 타 플랫폼 실무 조사 최소 3곳 포함) ②3번 검증(서로 독립 출처) ③3번 검수(자기 반박·출처 확인·이전 발언 대조). 못 한 축은 "못 했다"고 명시. 정의 = CLAUDE.md:116.
  • 밖에서 찾기 전에 안을 먼저(⓪-5): lib/revdcf/registry.ts(재료 원장) → data/sources/(원본 보관소) → Supabase 실제 행 → link_hub(외부 사이트 목록) 4곳을 먼저 연다.
  • 근거 좌표 의무: 이미 내려진 결정에 대해 단정할 때는 파일:절 좌표를 단다. 못 달면 "내 추측"이라고 명시.
  • 낱말의 뜻을 Cowork이 정하지 않는다 — 뜻이 갈릴 수 있으면 분석 전에 되묻는다.
  • 순서·우선순위를 Cowork이 정하지 않는다 — 판정은 전부 장은태. Cowork은 선택지와 대가표만 만든다.
  • 확정 전에 실행물을 만들지 않는다 — 사용자의 확정("ㅇㅋ" 등)을 받은 뒤 설계·명령서·파일을 만든다.

11-3. 핵심 메커니즘

  • 렌즈 선계산 2-pass 크론(lib/lensPrecompute.ts): pass1 전 유니버스(시총 상위 1,000) 값 계산·직전 컷으로 저장 → 분포 p30/p70로 컷 재유도(lens_cuts upsert) → pass2 새 컷으로 상태 재매핑 + lens_state_changes diff. 순환 의존(컷←분포←값←컷)을 끊는 구조. 보호 장치: 커버리지 게이트(결측 많으면 컷 재유도·프루닝 금지, 전날 컷 유지) · 프루닝 3중 가드(부분 실행 대량삭제 방지).
  • 판정 컷 원칙: 임의 상수 금지 — 시장 분포에서 유도(p30/p70). 고정 표준값은 RSI 30/70·F-Score 3/7뿐. 컷 없으면 state='pending'(거짓 판정 금지). 라이브 계산과 선계산이 같은 컷을 읽어 판정 일치.
  • LLM 비용·남용 가드: 요약·브리핑 8종 라우트는 캐시 미스(=새 과금) 직전에만 blockLLM(봇 UA 차단 + IP 레이트리밋 12/분·100/시간·IP 미로깅). 캐시 히트는 무게이트. 캐시 키 = 검증된 본문 URL sha1(포이즈닝 방지).
  • 활성 시장 게이트: ACTIVE_MARKETS=["KR","US"] 단일 배열을 검색·관심·종목상세·사이트맵·/api/lens·/api/brief가 공유 — 파킹 시장 심볼은 400. 새 시장 개방 = 배열 한 줄.
  • 피처 플래그: REVDCF_ENABLED·Q1_ENABLED 서버 env(기본 OFF) — 화면 노출만 막고 데이터 배관은 가동. 켜는 것은 장은태 육안 검증+명시 승인 사항.
  • 반복 함정(전체 목록 = SYSTEM_MAP §10): Turbopack이 API 라우트 변경 자동갱신 안 함(.next 삭제 재기동) · [locale] 페이지 캐시 지시자 없으면 무한 정적 캐시 · Promise.all 하나 실패=전체 실패(심볼별 격리) · PostgREST 1000행 캡+.order() 없는 .range() 불안정(전체 조회는 반드시 fetchAllRows()) · .in() 대량 심볼 URL 초과 조용한 실패(1,000개 청크) · git 미추적 파일을 소스에서 참조 금지(로컬 빌드는 통과해도 Vercel 클린 빌드가 깨짐 — 38시간 배포 정지 사고의 원인).
