## ⓪-4 반증조건 판명

**전제①(주장 정합)** — ㉠㉢은 참(코드·i18n 무모순). **㉡은 부분** — 아래 「결함① 상세」.

**전제②(배당 조정)** — **틀렸다(=raw임을 확인) → 결함으로 확정.** `lib/lenses.ts:196` `const closes = d.closes;`(momentum만 `d.adjCloses ?? d.closes`를 씀, 197~284 grep 확인). 공개 문구(`lensCopy.ts` technical 블록) 어디에도 배당 조정 언급 0건. **③저변동 신규①과 뿌리가 같다** — 저변동(`lowvol.ts`)도 `d.closes` raw. 개별 결함 2건이 아니라 **하나의 공통 결함이 두 렌즈에서 반복**되는 것으로 적는다.

**전제③(pos52=52주 위치)** — **부분적으로 틀렸다(가드 비대칭).**
- `sma(closes, n)`(`lib/technical.ts:4~9`): `closes.length < n → null`. **가드 있음 → 결함 아님.**
- `rsi(closes, period=14)`(`technical.ts:15~35`): `closes.length < period+1 → null`. **가드 있음 → 결함 아님.**
- `pos52`(`lib/lenses.ts:201~204`): `win = closes.slice(-252)`; `hi/lo = win.length ? max/min : null`. **최소 길이 조건이 `win.length>0`뿐 — 사실상 가드 없음.** 종가 2일치만 있어도(가격이 다르면 `hi>lo`) "52주 위치"라는 이름으로 숫자가 나온다. **확정 결함.**

## 결함① 상세 — verdict 톤이 "지금 상태 표시"와 어긋나는 지점은 텍스트가 아니라 집계 레이어

`lensCopy.ts`의 technical `up`/`down` 텍스트(`"상승 추세" / "지금 가격이 장기 평균선 위에 있어요. 단기 흐름을 빠르게 훑는 참고용이에요."`)는 **완전히 서술적·중립적**이다 — "좋다/나쁘다" 판단어가 없다. `readOf`가 만드는 개별 카드 문구 자체는 밸류 렌즈가 STEP805~806에서 받은 "절대→상대 중립화" 처리가 필요 없을 만큼 이미 안전하다(밸류의 문제는 "절대 임계값에 절대 방향 문구"였는데, 기술은 애초에 판단어를 안 쓴다).

🔴 **그러나 `verdict.tone`(`"pos"`/`"warn"`) 자체는 살아 있고, 이게 흘러가는 곳이 있다.** `lib/lensTones.ts`의 `STATE_SPEC`은 **7개 렌즈를 전부 동일한 구조**(`[pos상태, warn상태, mid상태]`)로 취급한다:

```
momentum: ["up","down","flat"], technical: ["up","down","flat"], valuation: ["cheap","rich","mid"],
lowvol: ["calm","jumpy","mid"], quality: ["high","low","mid"], assetgrowth: ["conservative","aggressive","mid"], fscore: ["strong","weak","mid"]
```

`toneForKey`·`tonesFromStates`·`tonesFor`·`firstPosLens`는 **등급(`strong`/`ref` 등)을 전혀 보지 않는다.** 실사용처(전수 grep):

| 소비처 | 무엇에 쓰이나 |
|---|---|
| `app/api/watchlist/quotes/route.ts` | 관심목록 행별 "강점 N·주의 N" 요약 |
| `app/api/explore/lens-top/route.ts` | `firstPosLens` — **보드 상위 종목 자동 미리보기의 "대표 렌즈" 배지**(STEP744/745 "거래 상위 예시") |
| `app/api/krx/ranking/route.ts`·`app/api/yahoo/{us,gb,jp,vn,cn}-list/route.ts` | 6개국 보드 리스트 행 톤 요약 |

`STATE_SPEC` 삽입 순서는 `momentum, technical, valuation, ...` — **기술이 두 번째**다. 즉 어떤 종목의 모멘텀이 `up`이 아니고 기술만 `up`이면, **`reference`(검증 안 됨) 등급의 200일선 신호가 그 종목의 대표 "강점" 배지가 된다** — 화면 어디에도 "이건 참고용 등급입니다"라는 구분이 이 집계 레이어엔 없다.

🔑 **이것이 결함이다.** `note`가 "매매신호 아니라 지금 상태 표시일 뿐"이라고 개별 카드에서는 정확히 밝히지만, 그 상태가 요약·랭킹·대표배지로 **압축되는 순간 다른 검증된 렌즈와 구분 없이 "강점"으로 셈해진다.** 개별 카드 문구(C-1 #7 "화면 일관성"의 카드 층위)는 무모순이나, **집계 층위(관심목록·보드·대표배지)에서는 문구가 약속한 "참고용" 지위가 사라진다.**

## 결함② — 가격 계열 배당 미조정(공통 결함, ③저변동과 동일 뿌리)

`d.closes`(raw)를 RSI·SMA200·52주 고저 셋 다 사용(`lenses.ts:196`). `d.adjCloses`(배당조정)는 momentum 하나만 쓴다(`lenses.ts:147`). 배당을 많이 주는 종목(리츠·유틸리티 등)은 배당락일마다 raw 종가가 인위적으로 떨어지므로, 200일선 대비·52주 위치가 실제 총수익 흐름보다 체계적으로 낮게 나올 수 있다. `lensCopy.ts` technical 블록에 이 사실 언급 0건 — ⓪-3b가 이미 공개한 세 한계(RSI 경험칙·매매신호 아님·모멘텀 중복)에 배당조정 문제는 **없다** → 이중 계상 아님, 신규 결함.

## 결함③ — `pos52`(52주 위치) 최소 표본 가드 없음

위 ⓪-4③ 표 참조. `sma200`·`rsi`는 코드에 명시적 `null` 반환 가드가 있어 **자기 자신이 부족한 데이터임을 스스로 밝힌다**(결측=na로 화면에 정직하게 뜸). `pos52`는 그런 장치가 없어, 상장 며칠 안 된 종목이라도 확보된 종가가 2개 이상이고 그 사이에 가격 변동만 있으면 "52주 위치 X%"라는 숫자가 그대로 나간다 — **이름과 실제 계산 기간이 어긋나는 정직성 문제**(C-1 #5 경계 처리 미비).

🔴 **비율 실측은 구조적으로 불가**: `lens_scores`엔 `technical_value`(=ma200vs)·`technical_state`만 저장되고 `rsi14`·`pos52w`는 저장되지 않는다(스키마 확인, `④감사`가 quality의 grossProfit/costOfRevenue에서 찾은 것과 같은 패턴 — 표시용 세부값은 캐시되지 않음). 외부 신규 취득도 이 STEP엔 금지돼 있어, **몇 %가 이 문제에 해당하는지 직접 잴 수 없다.** 대신 `sma200` 자체가 `null`(=200일 미만 데이터)인 종목 수를 하한 프록시로 잡는다: **16/999(1.6%)**(아래 DB 실측) — 이 16종목은 확실히 "200일 미만"이라는 조건에 해당하고, 그중 종가가 2일 이상만 확보돼 있으면 `pos52`는 (200일 요건과 무관하게) 계속 계산된다. **정확한 비율은 미측정**이나 하한은 실재한다.
