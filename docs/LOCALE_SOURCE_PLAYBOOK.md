# 🌍 LOCALE_SOURCE_PLAYBOOK — 언어권 데이터 소스 발견·검증·기록 지침

> **이 문서 = "런북(프로그램)"이고, 실행 엔진은 LLM(Cowork)이다.**
> 목적: 한 언어권(locale)을 붙일 때 필요한 데이터 소스(관심 신호·공시·지수·매매처 등)를 **어떻게 찾고·검증하고·기록하는가**의 *방법*을 코드화한다. 값(예: "서학개미")을 박아두는 게 아니라, **그 값에 도달하는 방법과 그 값이 무엇인지의 정의**를 남긴다.
> 새 언어권 온보딩 = 이 지침을 **순서대로 실행** → 산출된 per-locale 값은 그 locale에 정당하게 고정(추적 가능).
> 관련: `docs/COUNTRY_TAB_PLAYBOOK.md`(국가 탭 표준 틀) · `docs/LENS_DEV_PLAYBOOK.md`(기법 문제해결 로그·조건부 교훈 원칙) · `docs/UI_BROKER_LENS_REDESIGN.md`.

---

## 0. 왜 이 문서인가 (철학)

- **값이 아니라 방법을 코드화한다.** "서학개미"는 KR의 *이름표*일 뿐. 전이(transfer)되는 건 그 위의 **개념 정의**("자국 리테일의 국가별 해외 보유·순매수 공식 통계")다.
- **하드코딩 ≠ per-locale 값 고정.** locale마다 값이 다른 건 정상이고 옳다(각 나라 시스템이 다르므로). 나쁜 건 *그 값에 왜·어떻게 도달했는지 기록 없이* 박아두는 것.
- **LLM-네이티브 설계.** 결정론 코드로 50개국을 미리 예측하지 않는다. 정밀한 절차 + 판단 기준 + 실패 원장을 문서로 두고, LLM이 그 절차를 **실행**한다. 기록이 쌓일수록 새 locale 온보딩 능력이 좋아진다.
- **완성의 정의.** "한국어를 진짜로 완성" = KR 값을 이 지침의 *산출물*로 만들고(매직 리스트 아님), 그 과정을 여기 남겨 다음 locale이 재현 가능하게 하는 것.

## 1. 핵심 원칙 (5세트 — 이게 세트로 있어야 굴러감)

1. **LLM + 정밀한 방법**: 절차(§3)가 실제 결정 기준을 담아야 재현된다. "알아서 찾아라"는 금지.
2. **현실 검증 게이트(§4)**: LLM 출력(소스·엔드포인트)은 **지어낼 수 있다.** 반드시 라이브 프로브로 검증 후 채택. (이번 세션 실제 사례: TCBS 경로 추측 → 404.)
3. **인간 확정(타이브레이커)**: 애매한 판단 콜은 사용자와 대화로 확정. LLM이 단독 결정 X.
4. **실패 원장(§8)**: 안 된 것도 **왜** 안 됐는지 남긴다(다음이 같은 함정 회피).
5. **의미 우선 정의 + 조건부 교훈**: 개념은 "무엇"으로 정의(§2). 교훈은 **조건부**("이 조건/시장에선")로 — 무조건 참 금지(`LENS_DEV_PLAYBOOK §0` 계승).

## 2. 엔트리 스키마 — "의미 우선(무엇)" 4칸 + 발견 로그 3칸

각 데이터 소스는 아래 형식으로 기록. **①~④가 전이되는 정의, ⑤~⑦이 발견 기록.**

| 칸 | 내용 |
|---|---|
| ① **정체(무엇을 재나)** | 로케일 중립적·기능적 정의. 이름표 금지. |
| ② **목적(왜 필요)** | 이 데이터로 우리가 무엇을 하나. |
| ③ **필수 속성(진짜 '동등물' 조건)** | 이게 하나라도 빠지면 동등물 아님 → 폴백. (예: 국가별 분해·공식성·주기·공개접근) |
| ④ **인스턴스(locale별 실제 값)** | 그 locale의 실제 소스·엔드포인트·키 필요 여부. |
| ⑤ **시도(구체)** | 실제 검색어·URL·방법. |
| ⑥ **결과** | 됨/안 됨 + **왜**. |
| ⑦ **추상 교훈(조건부)** | 다른 locale에 전이될 규칙. "이 조건에선…". |

> 원칙: **①(정체)를 정확히 쓰는 순간, 다른 locale에서 그 "무엇"을 그대로 검색·판단할 수 있다.** ④(이름표)만 남기면 전이 안 됨.

## 3. 발견 절차 (결정 트리 — 순서대로)

새 locale의 어떤 데이터가 필요하면:

**STEP 1 — 개념 정의(무엇) 먼저 확정.** §2의 ①②③을 쓴다. (검색 전에 "무엇을 찾는지"를 못 박아야 헛짚지 않음.)

**STEP 2 — 자국 공식/규제기관 소스 우선 웹검색.** 신뢰·완전성 순: **규제기관/거래소 공식 > 공식 지정 사이트 > 상업 애그리게이터 > 뉴스.** (예: 공시 = KR DART·US EDGAR·JP EDINET·CN cninfo = 각국 지정 공식.) `WebSearch`로 소스명·엔드포인트·파라미터 구조 확인.
- 🔑 **client 라이브러리가 있으면 소스로 역이용**: 그 언어권 데이터를 다루는 파이썬/JS 라이브러리(예: vnstock)의 **소스코드에서 실제 엔드포인트를 읽는다.** (GitHub raw가 `web_fetch`로 빈값이면 `pip install <lib>` 후 `site-packages`에서 직접 grep.)

**STEP 3 — 도달성 프로브 (⚠️ 로컬 ≠ 프로덕션).** §4 게이트로 실측. **반드시 Vercel(데이터센터 IP)에서도** 확인(배포 후 `/api/...` 직접 호출). 로컬만 되면 실효 없음.

**STEP 4 — 응답 구조 + 필수 속성(③) 검증.** JSON 필드·HTML 구조를 실제 응답으로 확인. ③를 만족하는가? (예: 국가별 분해가 실제로 되나?)

**STEP 5 — 폴백 사다리.** 공식 소스가 막히면 순서대로: **공식 API → 공식 사이트 서버렌더 스크랩 → 상업 애그리게이터(원문 링크 귀속) → 뉴스/대체 지표.** 각 단계 실패는 ⑥에 이유 기록.

**STEP 6 — 인간 확정.** 소스가 둘 이상이거나 ToS·품질이 애매하면 사용자와 대화로 확정.

**STEP 7 — 기록.** §2 스키마로 이 문서에 엔트리 추가(§5·§6·§8). **그때그때** — 몰아서 금지.

## 4. 검증 게이트 (이번 세션에 실제로 걸린 것들 — 반드시 통과 확인)

- **G1. `web_fetch`/브라우저 프리뷰는 JSON·AJAX 본문을 삭제(빈값)로 보여준다.** → **"web_fetch 빈값 = 소스 죽음"이 절대 아님.** 실제 `fetch()`(Next 라우트)·`curl`·프로브 스크립트로 재확인. (이번 세션 반복 발생.)
- **G2. Vercel(미 데이터센터 IP) 차단.** 자국/데이터센터 IP를 막는 소스 있음(전례: 东方財富=exit52/502, KR·데이터센터 차단). **배포 후 프로덕션에서 직접 호출로 실측.** 막히면 UA/Referer 조정 → 대체 소스.
- **G3. API 키 필요 여부.** data.go.kr·EDINET 등은 키 필요 → **키는 사용자가 발급해 `.env`/Vercel 대시보드 등록**(Cowork는 키 취급 불가). `.env.local`은 로컬 전용 → 프로덕션은 Vercel 등록 + **재배포** 필수(배포 시점에 구워짐).
- **G4. JS 렌더·토큰.** 표/행이 정적 HTML에 없고 JS로 렌더되거나(예: Vietstock 공시행), 반위조 토큰이 JS 주입(예: Vietstock `__RequestVerificationToken`)이면 서버 fetch로 못 얻음. → 네트워크 캡처(Chrome MCP `read_network_requests`) 또는 대체.
- **G5. 인코딩/디코딩.** 링크가 서버측에서 디코딩 불가한 경우(예: Google News `/rss/articles/CBMi…` = JS 전용 디코딩·서버 fetch 400) → 원문 URL 확보 불가 → 폴백/스킵.
- **G6. 경로 추측 금지.** 죽은/이동된 엔드포인트를 추측으로 때우지 말 것(전례: TCBS `tcanalysis/v1/ticker/...` 404). 네트워크 캡처·라이브러리 소스로만 확보.
- **G8. 시간 예산 가드는 '새 작업 픽'만 막는다 (2026-07-18).** 진행 중 await는 못 끊음 → 타임아웃 없는 콜(예: `yf.chart`) 하나가 동시성 레인을 잠가 함수가 하드리밋까지 감. **파이프라인의 모든 외부 콜에 개별 타임아웃**(AbortSignal/Promise.race) 필수. (cn-perf 9일 장애의 한 축.)
- **G9. vercel.json 크론 스케줄 = 플랜 제약 검증 먼저 (2026-07-18).** Hobby = 일 1회 한도. 위반 스케줄이 들어가면 **그 커밋 이후 모든 배포가 조용히 거부**됨(webhook 정상·에러 표시 약함) → "코드 고쳤는데 안 바뀜"의 정체가 배포 미반영일 수 있음. **배포 반영 확인 = 라이브 sentry-release 대조**(캐시버스터 붙여서).

## 5. 관심 신호(relevance) — 첫 실제 인스턴스: KR "서학개미"

> 용도: 국가 탭 순서·티커 이웃 시장을 **그 언어권 기준 중요도**로 정렬(§7).

- **① 정체(무엇)**: 한 나라의 **리테일 투자자**가 **각 해외 시장에 보유·순매수한 금액을 국가별로 분해**한 공식 통계.
- **② 목적**: 그 언어권 사용자에게 해외 시장을 **관심 순으로 줄 세우기**(탭 순서·티커 큐레이션).
- **③ 필수 속성**: (a) **국가별 분해** 가능 (b) **공식/규제기관** 출처(신뢰) (c) 주기 **월/분기면 충분** (d) **공개 접근**(API·다운로드).
- **④ 인스턴스(KR)**: 한국예탁결제원 SEIBro / 공공데이터포털(data.go.kr) "외화증권 보관·결제 국가별 통계" 계열. **data.go.kr API 키 필요(사용자 발급).**
- **⑤ 시도**: 국가 선정 시 웹검색으로 "예탁결제원 국가별 외화증권 보관금액·순매수"를 확인(수동·1회). 라이브 파이프라인은 **미배선**(현재는 수동 근거).
- **⑥ 결과**: 데이터 존재·국가별 분해 확인. 파이프라인 배선은 UI 마무리 후 예정(키·주기 배선 필요).
- **⑦ 추상 교훈(조건부)**: "**자국 규제기관/예탁기관의 해외투자 통계**를 1순위 관심 신호로. 없으면 §7 폴백." ⚠️ 후행 지표(이미 산 곳=미국 독식)라 **신흥 관심 시장이 묻힘** → 순수 이 신호만 쓰지 말고 §7처럼 블렌딩. (조건: '정보 허브' 성격이면 관심·성장 신호 가중.)

> **다른 locale 적용법**: "일본판 서학개미"를 막연히 찾지 말고, **①의 정의("일본 리테일의 국가별 해외 보유·순매수 공식 통계")를 그대로 검색.** ③ 필수 속성 하나라도 빠지면 동등물 아님 → 폴백.

## 6. 공시 소스 엔트리 (이번 세션 실측 통합 — US·KR·JP·GB·CN·VN)

**VN 실패 상세(⑥)** — 다음 locale이 같은 함정 피하게:
- TCBS `apipubaws.tcbs.com.vn/tcanalysis/v1/ticker/...` → **404(경로 폐기·이동).** 경로 추측 실패.
- CafeF `Events_RelatedNews_New.aspx` → 200이나 **빈 `<ul>`**(세션/쿠키 필요).
- Vietstock 공시행 → **정적 HTML에 없음(JS 렌더)** + `__RequestVerificationToken` **JS 주입**(len=0) → 서버 fetch 토큰 불가(G4).
- Google News `<link>` `/rss/articles/CBMi…` → **서버 fetch 400(JS 전용 디코딩·batchexecute 필요, G5)** → 원문 URL 확보 0% → R1 보류.
- 최종: 이벤트층=Google News(vi) 뉴스, R3 한국어 뉴스요약으로 커버. **공식 공시 R1은 소스 부재로 보류**(사용자 승인).

## 7. relevance 규칙 (탭 순서·티커 큐레이션 — 코드로 만들 함수)

```
relevance(locale, market):
  if market == locale.home: return +∞          # 자국 고정 1순위
  score =  w1 * globalMarketCap(market)         # 객관(야후)
         + w2 * crossBorderInterest(locale→market)  # §5 신호, 있을 때만
         + w3 * proximity(locale, market)        # 지역 인접(참조데이터)
  return score

신호 우선순위(codified): 자국 규제/예탁 해외투자 통계 > 거래소 거래대금 > 자체 행동데이터
폴백: crossBorderInterest 없으면 w2=0 → (시총 + 인접)으로 결정
```
- **tabOrder** = 자국 → relevance 내림차순 (+ N개 초과 시 "더보기" 오버플로우).
- **tickerSet** = 자국 지수 + **글로벌 앵커**(US 지수·금·BTC·유가 — 전 locale 공통) + 자국통화 환율 + relevance 상위 이웃의 대표지수.
- **가중치 w1·w2·w3·앵커 집합** = **전 locale 공통 정책 파라미터**(하드코딩 아님·바꾸면 일괄 적용). 순수 자동 파생의 천장은 여기 — 정상.

## 11. 🅿️ 보류 기능 프로토콜 (Parked Feature Protocol) — 표준 단계

> **트리거**: 어떤 소스/기능을 §3~4의 방법·게이트를 **다 동원했는데도** 우리 실행환경(Vercel 등)에서 안 됨(예: HNX=VCI가 클라우드 IP 차단). **그리고** 억지로 채우면 가짜/유령 데이터가 됨.
> **원칙**: **가짜로 채우지 않는다.** 대신 **"작동하는 코드는 남기고 스위치만 OFF"**(parked feature) — 나중에 조건(예: VPS)만 갖추면 즉시 켜지게 배선을 완비해 둔다. (은태님 확정 2026-07-09.)

**표준 절차 (막힌 소스 만나면 이 순서):**
1. **커버되는 부분으로 즉시 복구** — 사용자 화면이 깨지지 않게(예: VN=HOSE 403 Yahoo). 막힌 부분만 OFF.
2. **작동 코드 보존** — 로컬/특정 IP에선 되는 페처 스크립트를 삭제하지 말고 `scripts/*_parked.mjs`(또는 명확한 이름)로 남김. 헤더에 "PARKED·어디서만 동작·활성화 문서 링크".
3. **`docs/PARKED_{기능}_ACTIVATION.md` 작성** — ① 왜 보류(한 줄) ② 이미 깔아둔 배선(검증된 요청 형태·스크립트·데이터 소스·DB) ③ **활성화 체크리스트**(조건 갖추면 이대로만 하면 켜짐) ④ 비용·노력 ⑤ 재사용 범위.
4. **원장 기록** — §8 실패원장 + (해당되면) §4 게이트에 조건부 교훈 추가.
5. **세션 종료 체크리스트**(CLAUDE.md)에서 보류 기능 보존 확인.
