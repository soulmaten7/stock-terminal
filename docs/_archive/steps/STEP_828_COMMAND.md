## §1 — 🔴 공시요약 프롬프트 인젝션 + 출력 가드 부재 (최우선)

### 문제

- `app/api/kr-events/summary`(`nm`) · `jp-events/summary` · `cn-events/summary` · `gb-events/summary` · `vn-events/summary` · `events/summary`(`items`)에서 **클라이언트가 준 문자열이 검증·이스케이프·길이제한 없이 LLM user 프롬프트에 삽입**된다.
- 산출물은 **전 사용자 공유 캐시**(`filing_summaries`)에 저장된다.
- 🔴 **이 6개 라우트엔 출력 가드가 전혀 없다** — `containsBannedWords`/`passesGuard`는 `/api/brief`와 `daily-brief`에만 있다.
- 결과: 무인증 공격자가 `nm`에 지시문을 넣어 **"지금 매수하세요" 같은 추천 문구가 담긴 공시 요약을 전 사용자에게 영구 노출**시킬 수 있다.

### 조치

1. **입력 정화**: `nm`·`items` 등 클라 제공 문자열에 **길이 상한 + 화이트리스트 문자셋** 적용. 🔑 더 나은 방향은 **클라를 신뢰하지 않는 것** — 종목명을 우리 DB(`kr_stock_snapshot`·`us_symbols` 등)에서 조회해 쓰고, 클라 값은 무시하거나 대조용으로만. 가능한 라우트는 그렇게 하고, 불가하면 정화 후 사용(어느 쪽을 택했는지 라우트별로 보고).
2. **출력 가드 적용**: 6개 라우트 전부에 `/api/brief`·`daily-brief`가 쓰는 **금지어 검출 + 실패 시 저장 거부**를 적용. 🔑 공시요약은 결정론 폴백이 없으므로, 가드 실패 시 **캐시에 저장하지 않고 요약을 숨긴다**(빈 응답 → 화면은 기존 결측 처리). 지어내지 말 것.
3. **프롬프트 구조**: 사용자 제공 값이 지시문으로 해석되지 않게 **데이터 영역으로 분리**(구분자·역할 분리 등 라이브러리/모델이 지원하는 방식).
4. **기존 캐시 점검**: `filing_summaries`에 이미 오염된 행이 있는지 **금지어 스캔**으로 확인하고, 있으면 삭제 후 보고(Cowork가 MCP로 확인 가능하므로 **쿼리와 결과를 보고에 기재**).

## §2 — 🔴 유니버스 붕괴 시 대량 삭제

### 문제

- `lib/lensPrecompute.ts`의 `topByMarketCap`이 야후 배치 쿼트 청크 실패를 `catch {}`로 조용히 스킵한다 → 부분 장애 시 유니버스가 1,000 → 400으로 쪼그라든다.
- 806 §3의 프루닝 가드는 **`saved / universe.length`**만 보므로 400/400 = 100%로 통과 → **나머지 600종목의 `lens_scores`가 삭제**된다.
- universe=0이어도 `{ok:true, computed:0}`를 **200으로 반환**하고 **Sentry 알림이 없다** → 탐지는 다음날 health뿐(실제로 16시간 무감지 사례 발생).

### 조치

1. **유니버스 하한 가드**: 유니버스 크기가 **기대치 대비 일정 비율 미만**(예: 직전 성공 실행의 70% 또는 절대 하한)이면 **프루닝을 건너뛰고 계산도 중단**하거나 최소한 저장만 하고 삭제는 안 한다. 기준값과 근거를 보고에 기재.
2. **청크 실패 가시화**: `catch {}`를 **실패 카운트 집계 + Sentry**로. 실패 청크가 일정 비율을 넘으면 유니버스를 신뢰하지 않는다.
3. **universe 0/과소 알림**: `{ok:true, computed:0}` 대신 **Sentry 캡처 + 응답에 경고 플래그**. 크론이 "성공"으로 기록되지 않게.
4. **pass2 실패 시 프루닝 스킵**: 현재 pass2 실패를 Sentry 캡처 후 **그대로 진행**해 프루닝이 실행된다 → pass2 실패 시 **프루닝을 건너뛴다**.
5. **health 보강**: `us_stock_perf`·`kr_stock_snapshot`이 **MAX(updated_at)만** 보고 있어 99% 실패해도 초록이다 → **신선 행 수 하한**을 추가. `lens_cuts` 나이도 감시 대상에 추가(판정 기준 자체가 묵으면 전 렌즈가 틀어진다).

## §3 — 🔴 크롤러 무방비 외부 API 호출

### 문제

- `app/[locale]/stock/[symbol]/page.tsx`가 `force-dynamic`이고, 요청마다 `lib/instrumentType.ts`가 **KR=네이버 비공개 API 1콜 / US=야후 quote 1콜**을 호출한다.
- 이 경로는 서버 컴포넌트라 `lib/rateLimit.ts`를 타지 않아 **봇 차단·레이트리밋이 전혀 없다.**
- 사이트맵이 **KR ~2,700 + US ~6,000 URL**을 광고 → 봇 1회 순회 = 외부 API 수천 콜 → 야후 쓰로틀 → **§2의 방아쇠**.
- `instrumentType`의 `_cache` Map에 **상한이 없다**(메모리 누수).

### 조치

1. **결과 캐시**: 종목 타입(주식/ETF)은 **거의 불변**이다 → `_cache`에 **상한 + TTL**을 두고, 가능하면 **DB나 정적 번들로 이관**해 외부 호출 자체를 없앤다(우리는 이미 심볼 번들·스냅샷을 가지고 있다). 외부 호출은 **미지 심볼일 때만** 폴백.
2. **봇 게이트**: 서버 컴포넌트 경로에도 봇 UA 판별을 적용해 **크롤러에는 외부 호출 없이** 렌더(캐시/폴백 값 사용). `lib/rateLimit.ts`의 봇 판별 로직 재사용.
3. **페이지 캐시**: `force-dynamic`이 반드시 필요한지 재검토 — 필요하면 유지하되 **외부 호출만 캐시**. (713~714의 캐시 stale 교훈: `[locale]` 페이지 캐시 지시자는 신중히. 바꾸면 그 이유와 검증을 보고에 기재.)
4. **사이트맵 유령 심볼 정리**: 이름이 해석되지 않는 심볼(상폐·미매핑)을 **사이트맵에서 제외**해 봇이 유령 URL을 훑지 않게(830의 SEO 항목과 겹치나, **비용 방어 차원에서 이번에 처리**).
