# ORDER — Trillion 국가 확장 구조 전환 (2026-09-05)

## 0. 이 ORDER가 존재하는 이유 (읽고 시작할 것)

지금 Trillion 화면은 **국가가 KR·US 두 개라는 전제로 하드코딩**돼 있다.
그런데 이 플랫폼의 계획은 두 채널이 자리를 잡으면(영상 업로드 안정화 +
레퍼럴 등 수익구조 세팅 완료) **다른 국가의 주식 정보 채널을 계속
추가하는 것**이다(일본·영국 등). 즉 국가 추가는 "혹시 하게 될지도 모르는
일"이 아니라 **확정된 로드맵**이다.

따라서 이 ORDER의 목적은 기능 추가가 아니라 **구조 전환**이다:

> **국가를 코드가 아니라 데이터로 다룬다.
> 새 국가 채널을 열 때 필요한 작업이 "데이터 한 행 추가"뿐이어야 하고,
> 화면 컴포넌트·i18n 키·조건문을 새로 고치는 일이 없어야 한다.**

이 문장이 이 ORDER의 판정 기준이다. 구현 방식이 여러 개일 때는 "일본
채널을 추가한다고 가정했을 때 코드를 고쳐야 하는가?"로 판단하고,
고쳐야 한다면 그 방식은 틀린 것이다.

**지금 하는 이유**: 리포트 데이터가 15건뿐이라 구조를 바꿔도 잃을 게
없다. 국가가 3개가 된 뒤에 바꾸면 마이그레이션이 훨씬 복잡해진다.

## 0-1. 이번에 같이 반영할 두 가지 (별건이지만 같은 화면을 건드림)

동시에 하는 이유는 셋 다 홈 카드·리포트 카드를 만지기 때문이다. 따로
하면 같은 파일을 세 번 고치게 된다.

**(A) 채널 카드에서 구독자수 표시를 빼고 채널 설명 한 줄로 교체**
- 이유: 신생 채널이라 실제 값이 스톡스카우터 34명·WeTheTicker 1명이다.
  사회적 증거로 쓰려던 숫자가 오히려 "아무도 안 보는 채널" 신호가 된다.
  설명 한 줄은 클릭할 이유를 준다.
- 🔴 **구독자수 기능 자체는 지우지 말 것** — `our_channels` 테이블
  컬럼·`our-channels` 크론·`refreshOurChannels()` 전부 그대로 두고
  **화면 표시만 끈다.** 나중에 숫자가 커지면 표시만 다시 켤 수 있게.
  (데이터는 계속 쌓여야 그때 추이를 볼 수 있다.)

**(B) 리포트에 제목(title) 추가**
- 이유: 지금 홈 카드가 "종목명 / 증권사·판정 / 목표가"뿐이라 클릭할
  이유(훅)가 없다. 그리고 **영상을 본 사람이 플랫폼에서 그 리포트를
  찾을 때 기억하는 것이 영상 제목**이므로, 같은 문구가 붙어야
  채널→플랫폼 이동이 끊기지 않는다.
- Trillion은 **받아서 표시만** 한다. 제목을 생성하지 않는다.
  채널이 채워 보낼 값의 규칙은 아래와 같다(참고용 — Trillion이 구현할
  것은 아님):
  - 영상 제작된 리포트 → 확정된 영상 제목(사람 검수 통과분)
  - KR 영상 미제작 → `reasons`의 첫 번째 title(리포트 본문 소제목)
  - US 영상 미제작 → 가이던스 원문 문장 한 줄(8-K에 적힌 그대로)
  - 전부 원문 기반이며 우리가 생성하는 문장은 없다(1군 원칙)

## 1. 지금 하드코딩된 지점 (실사 후 확정할 것)

아래는 조사에서 파악된 목록이며 **완전하지 않을 수 있다.** STEP 1에서
실제 코드를 훑어 "국가가 늘면 고쳐야 하는 곳"을 전수 조사해 보고할 것.

- `our_channels.channel_key`가 `kr`/`us` 값으로 고정
- 홈(`TodayClient.tsx`)이 KR 섹션·US 섹션을 각각 하드코딩해 렌더
- i18n 키가 국가별로 분리(`krReportsTitle`·`usReportsTitle` 등) — 국가가
  늘 때마다 키를 새로 만들어야 하는 구조
- 국기 이모지(🇰🇷🇺🇸)가 컴포넌트에 직접 박힘
- `/reports` 목록 페이지의 country 처리
- `lib/activeMarkets.ts`의 `ACTIVE_MARKETS=["KR","US"]` (이건 이미
  배열이라 확장 가능 — 유지할지 새 구조에 흡수할지 판단)
- 그 외 STEP 1에서 발견되는 모든 것

## 2. 목표 구조

**국가 메타데이터를 한 곳(데이터)에 모은다.** 어디에 둘지는 판단하되,
아래 조건을 만족해야 한다:

- 새 국가 추가 = 그 저장소(테이블 또는 설정 파일)에 **행/항목 하나 추가**
- 화면은 그 목록을 **순회(map)** 하며 섹션·카드를 자동 생성
- 국가별 문구(국가명·섹션 제목·채널 설명)는 **ko/en 양쪽이 데이터에
  담기거나**, i18n 키를 국가 코드로 조합해 찾는 방식(예:
  `countries.{code}.reportsTitle`) 중 하나 — 어느 쪽이든 **새 국가가
  컴포넌트 수정 없이 동작**해야 함
- 국기는 국가 코드에서 파생하거나 데이터에 저장(컴포넌트에 박지 말 것)
- 표시 순서는 데이터로 제어(`display_order`) — 코드에 순서를 박지 말 것
- 리포트가 아직 0건인 국가도 섹션이 뜨고 빈 상태 문구가 나와야 함
  (US가 지금 그 상태다)

**판단이 필요한 지점**(정하고 근거를 보고에):
- 국가 메타를 DB 테이블에 둘지, 코드 안 설정 파일(예: `lib/countries.ts`)에
  둘지. DB면 운영 중 추가가 쉽고, 설정 파일이면 타입 안전·배포 이력이
  남는다. 이 저장소 관례에 맞는 쪽으로.
- `our_channels`와 국가 메타를 한 테이블로 합칠지 분리할지(국가 1개 =
  채널 1개가 지금은 성립하지만, 한 국가에 채널이 둘 이상 생길 여지도
  고려).

## 4. STEP 구성

### STEP 1 — 실사 + 설계 보고 (변경 없음, 보고 후 대기)
1. 위 1절의 하드코딩 지점을 **전수 조사**(파일:줄). 목록에 없는 것도
   찾을 것 — 판정 기준은 "일본 채널을 추가하면 고쳐야 하는가".
2. 목표 구조 설계안: 국가 메타를 어디에 둘지, 스키마/타입, 화면이 어떻게
   순회할지, i18n 처리 방식. **2절의 판단 지점에 대한 결정과 근거 포함.**
3. `title` 컬럼 추가 마이그레이션 초안(적용은 STEP 2에서).
4. 검증 시나리오: "가상의 일본(JP) 국가를 데이터에만 추가했을 때 코드
   수정 없이 홈에 섹션이 뜨는가"를 어떻게 확인할지.
5. 보고 후 대기.

### STEP 2 — 확정 후 실행
1. 국가 메타 구조 신설 + 기존 하드코딩 제거(홈·`/reports`·i18n·국기·순서).
2. `channel_reports.title` 컬럼 추가(MCP `apply_migration`으로,
   **CLI `db push` 금지**). 홈 카드·종목 페이지 리포트 헤더에 title이
   있으면 한 줄 표시, 없으면 지금처럼 증권사·판정만(억지로 채우지 않음).
   기존 15건은 NULL이라 안 뜨는 것이 정상 — 채널이 재push하면 채워진다.
3. 채널 카드: 구독자수 표시 제거 → 채널 설명 표시(0-1의 (A) 그대로,
   **기능은 유지·표시만 끔**).
4. **확장성 실증 테스트**: 국가 메타에 가상의 JP 항목을 임시로 추가해
   홈에 섹션이 코드 수정 없이 뜨는지 확인하고, 확인 후 **반드시 원복**.
   결과를 보고에 적을 것(이 테스트가 이 ORDER의 성공 판정이다).
