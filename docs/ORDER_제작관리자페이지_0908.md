# ORDER — EarthTicker 제작 관리자 페이지 (2026-09-08)

채널이 만드는 콘텐츠(리포트형·성장스토리, 한국·미국)의 **제작 진행 상태를
한곳에서 보고 관리**하는 관리자 페이지를 만든다.

## 왜 필요한가

지금은 "무엇을 만들었나"가 흩어져 있다 — 텔레그램 메시지, 에피소드 폴더의
youtube.md, 채널 저장소의 원장(coverage.json), EarthTicker DB. 편수가
적을 땐 텔레그램 스크롤로 찾았지만, 주 9편 × 두 채널이면 한 달 70편이라
곧 감당이 안 된다.

**구글 시트를 새로 만들지 않는 이유**: 데이터가 이미 EarthTicker DB에
대부분 있다. 시트를 따로 두면 두 곳이 어긋났을 때 뭐가 맞는지 모르게
된다. 이미 있는 데이터 위에 화면만 얹는 게 맞다.

## 상태 흐름 — 무엇이 자동이고 무엇이 사람 몫인가

| 상태 | 누가 채우나 | 언제 |
|---|---|---|
| 대기 중 | 자동 | 대기열 생성 시(한국 19:30 / 미국 08:00) |
| 기획됨 | 자동 | 조립 시점에 plan.md 존재를 보고 소급 체크 |
| 조립됨 | 자동 | 조립·텔레그램 발송 완료 시 |
| **업로드됨** | **사람이 체크박스 클릭** | 유튜브·인스타 업로드 후 |

**업로드만 사람 몫인 이유**: 업로드가 수동이라 시스템이 알 수 없다.
그리고 이게 사용자가 원한 "체크박스로 관리"의 핵심 — 관리자 페이지에서
업로드 안 한 것만 눈에 띄면 된다.

**코덱스 기획이 실시간 자동이 아닌 이유**: 코덱스는 EarthTicker DB에
접근할 수 없다. 대신 클로드 코드가 조립할 때 plan.md가 있는 걸 보고
소급 체크하면 결과는 같다.

## STEP 1 — 설계 보고 (구현 전 대기)

### 1-A. 데이터 구조
- 지금 있는 것: `channel_reports`(리포트형), `channel_growth_stories`(성장
  스토리). 여기에 제작 상태를 담을지, 별도 상태 테이블을 둘지 판단.
  - 고려: 대기열 단계(아직 조립 전)는 이 테이블들에 행이 없다. 즉
    "대기 중"을 표현하려면 조립 전에도 행이 생기거나 별도 테이블이 필요.
- 담아야 할 것: 종목·국가·유형(리포트형/성장스토리)·날짜·제목·상태·
  업로드 체크·유튜브 링크(사람이 나중에 넣을 수도)
- 🔴 유튜브 제목·설명·인스타 캡션은 지금 적재를 안 하고 있다(에피소드
  폴더의 youtube.md·instagram.md에만 있음). 관리자 페이지에서 보려면
  적재가 필요 — 이 부분은 채널 저장소 작업이라 이번 범위 밖이지만,
  스키마에 자리를 만들어두고 "채널 쪽에서 채울 예정"으로 표시.

### 1-B. 화면
- `/admin` 하위에 배치(기존 관리자 구역 관례 따르기). 로그인·권한은
  기존 admin 인증 그대로.
- 표 형태: 날짜 · 국가 · 유형 · 종목 · 제목 · 상태 · 업로드 체크박스
- 필터: 국가(KR/US), 유형(리포트형/성장스토리), 상태(업로드 안 한 것만
  보기 등), 날짜 범위
- 정렬: 최신순 기본
- 체크박스는 클릭 즉시 저장(별도 저장 버튼 없이)
- 모바일에서도 볼 수 있게(폰으로 확인할 일이 많음)

### 1-C. 자동 상태 갱신 경로
- 조립 완료 시 채널이 이미 EarthTicker에 적재하고 있다. 그 시점에 상태를
  같이 보내면 되는데, 채널 쪽 스크립트 수정이 필요하다 — 그건 별도
  작업이니 이번엔 **EarthTicker 쪽 수신 준비**(API·스키마)까지만.
- "대기 중" 상태를 어떻게 만들지 판단 — 채널의 대기열 생성 시점에
  EarthTicker로 보낼지, 아니면 조립될 때 한꺼번에 기록할지. 전자가
  정확하지만 채널 작업이 늘어난다.

### 1-D. 판단해서 제안할 것
- 상태를 별도 테이블 vs 기존 테이블 컬럼 추가 — 국가 확장 원칙(컬럼이
  계속 늘어나는 구조 회피)과 충돌하지 않게
- "대기 중" 단계를 실제로 표현할 가치가 있는지 — 없으면 "조립됨 /
  업로드됨" 두 상태만으로도 충분할 수 있다
- 기존 admin 페이지 구조·인증을 어떻게 재사용할지
