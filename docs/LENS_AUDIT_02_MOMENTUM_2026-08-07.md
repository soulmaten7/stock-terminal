## 🟢 먼저 — 잘 돼 있는 것

**12-1 계산이 정확하다** (`lib/momentum.ts:19~24`)
```ts
const p12 = closes[closes.length - 252];
const p1  = closes[closes.length - 21];
return momentum121(p12, p1);
```
t−252 → t−21 수익률. **최근 1개월을 정확히 제외**한다. 원전(prior 2-12)과 일치.

**문구가 정직하다.** note가 스스로 이렇게 적고 있다:
> *"세기(t·샤프)는 표본 구간에 따라 흔들려 **특정 값으로 못박지 않고**, 수익 '수준'은 **생존편향·동일가중으로 부풀려져 실전 기대치가 아니에요**(방향이 맞다는 뜻이지 수익 보장 아님). ⚠️ 12~18개월 뒤 부분 반전·**모멘텀 크래시**가 알려진 실패 모드예요. 판정은 시장 분포 순위(상하위 30%)라 절대 방향이 아니에요(**생존자 상위 1,000 사이 순위**)."*

🔑 **밸류 렌즈와 비교하면 수준이 다르다.** 821의 주장 정합 작업이 실제로 작동했다.

## 🔴 결함 ① — 단기(short) 신호가 창작이고 최근 1개월이 이중 계산된다

```ts
const r1 = ret(closes, 21), r3 = ret(closes, 63);
short: labelOf(locale, "trend", shortState(avg([r1, r3])))
```

- `r3`(63일 수익률)은 **`r1`의 21일을 포함한다.**
- 그 둘의 **산술평균**을 낸다 → 🔴 **최근 1개월이 두 번 들어간다.**
- 🔴 **기간이 다른 두 수익률을 평균하는 절차는 어떤 원전에도 없다.** 제가디시·티트만에도, 카하트에도, FF에도 없다. **우리 창작이다.**

그리고 이 값이 화면 **「단기」축**에 그대로 표시된다(`StockLensClient.tsx:337` `horizon.short`).

🔴 `CLAUDE.md` 🚫 **창작 금지** — *"원전에 없는 산출물·지표를 추가하지 않는다"* 정면 위반.

## 🔴 결함 ② — ±5% 절대 임계값이 근거 없이 박혀 있다

```ts
// 단기(1·3개월 평균)용 상태 — 별개 신호(단기 추세)라 분포컷 대상 아님(고정 ±5%·기존 동작).
const shortState = (v) => v == null ? null : v > 5 ? "strong" : v < -5 ? "weak" : "neutral";
```

전수 검색 결과 **±5%의 근거가 저장소 어디에도 없다.** 주석의 사유는 *"기존 동작"*뿐이다.

🔑 **STEP 820이 기술 렌즈에서 RSI 30/70을 *"학술·업계 표준"*이라 적은 것을 *"와일더 관습적 기준"*으로 정정했다.** 그때의 기준을 이 줄에 적용하면 — **±5%는 와일더 같은 관습조차 없다.** 출처가 0이다.

게다가 모멘텀 렌즈의 나머지는 전부 **상대(분포) 판정**인데 **단기만 절대 임계**다. 한 카드 안에서 판정 원리가 두 개다(820이 잡아낸 것과 같은 유형).

🔴 **이것이 「하드코딩」의 정확한 실물이다.**

## 🔴 결함 ③ — 배당조정 폴백이 잣대를 섞고, "정직 표기용" 플래그를 표기하지 않는다

```ts
// lib/lensCompute.ts:129~130
adjComplete = allAdj;
adjCloses = allAdj ? adjs : raws;   // 🔴 전 구간 유효할 때만 조정, 아니면 raw

// lib/lenses.ts:147
const closes = d.adjCloses ?? d.closes;
```

**어떤 종목은 총수익률(배당 포함), 어떤 종목은 가격수익률(배당 제외)로 12-1이 계산된다.**

- 🔴 배당수익률이 높은 종목(유틸리티·통신·리츠)이 raw로 계산되면 12-1이 **체계적으로 낮게** 나온다 → 하위권으로 밀린다.
- 🔴 **그리고 그 값들이 같은 분포 컷(p30/p70)에 들어간다.** 컷 경계 자체가 오염된다.

플래그는 있다. `lib/lenses/types.ts:63`:
> `adjUsed?: boolean; // 계열 전체가 유효 adjclose였는지(STEP 808 §9) — false면 adjCloses=raw. **정직 표기용.**`

🔴 **그런데 전수 grep 결과 `adjUsed`는 `lib/`에만 3건이고 `app/`·`components/`·`messages/`에 0건이다. 화면에 뜨지 않는다.**

🔑 **"정직 표기용"이라 만들어놓고 표기를 안 한다.** STEP 819의 교훈 *"카피를 잘 써도 렌더 안 하면 0"*이 데이터 필드에서 재발했다.

🔑 그리고 이 결함은 **밸류 결함 ③(TTM PER과 연간 PER을 한 분포에 섞음)과 구조가 완전히 같다.**
> **폴백이 잣대를 바꾸는데 분포는 하나다.** 두 렌즈에서 같은 패턴이 나왔으므로, 나머지 5개도 이 축으로 확인해야 한다.

## 🟡 결함 ④ — 파마-프렌치 관행 부분 오귀속

**우리 note**:
> *"우리 계산 사양(최근 1개월 제외·상하위 30%)은 **카하트(1997) UMD·파마-프렌치 모멘텀 팩터의 관행**이에요."*

**원전 확인** — Ken French 공식 데이터 라이브러리 원문:
> *"six value-weighted portfolios"* · 사이즈 2분할 **"the median NYSE market equity"** · *"The monthly prior (2-12) return breakpoints are the **30th and 70th NYSE percentiles**."* · `Mom = 1/2(Small High + Big High) − 1/2(Small Low + Big Low)`

| 항목 | FF/Carhart | 우리 |
|---|---|---|
| 형성 기간 prior (2-12) | ✅ | ✅ **일치** |
| 30/70 백분위 | ✅ | ✅ 숫자는 일치 |
| **사이즈 2분할(NYSE median)** | **필수** | 🔴 **없음** |
| **브레이크포인트 출처** | **NYSE 종목** | 🔴 자체 유니버스(시총 상위 1,000) |
| 가중 | value-weighted 포트폴리오 | 🔴 개별 종목 줄세우기 |

🟡 **다만 우리는 팩터 포트폴리오를 만드는 게 아니라 개별 종목을 줄 세우는 것**이므로 사이즈 분할·가중은 원래 적용 대상이 아닐 수 있다. 문제는 **주장 방식**이다 — *"FF 관행이에요"*라고 하면 사용자는 *"FF대로 했구나"*로 읽는다.

🔴 **정확한 문구는 "관행이에요"가 아니라 "형성 기간과 30/70 구분은 따랐고, 사이즈 분할·NYSE 브레이크포인트는 따르지 않았다"이다.**

🔑 STEP 815의 교훈 재발 — *"'원전대로'라 적은 것도 원전을 다시 열어봐야 한다."*
