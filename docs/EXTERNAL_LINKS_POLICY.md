# 외부 링크 열기 & 번역 정책 (External Links & Translation Policy)

> 결정 기록. 앱 개발 시 이 규칙을 그대로 따른다. (2026-07-01 확정)

## 결정 (Decision)
외부 목적지 사이트(東方財富·日経·SCMP 등) 링크는 다음으로 연다:
- **기본: 인앱 브라우저 탭** — iOS `SFSafariViewController` / Android `Chrome Custom Tabs`
- **보조: "외부 브라우저에서 열기" 옵션** (파워유저·자기 로그인 세션 그대로 쓰고 싶은 소수)
- **금지: 생 웹뷰(WKWebView / Android WebView)** — 브라우저 번역 안 됨 + 보안·유지보수 부담 + 남의 콘텐츠 책임

## 근거 (Why) — 글로벌 플랫폼 = 리텐션이 핵심
인앱 커스텀탭이 세 마리를 다 잡음:
1. **리텐션** — 스와이프 한 번에 앱 복귀. 외부 브라우저로 넘기면 사용자가 앱을 완전히 이탈.
2. **번역** — 사파리·크롬 엔진 기반이라 브라우저 자동번역이 그대로 동작. → **별도 번역 기능 만들 필요 없음.**
3. **로그인·세션 유지** — 목적지 사이트 계정 유지.
4. 제품 레이어 유지 — 상단 바에 번역 힌트·공유·저장 등 얹을 여지.
5. 글로벌 표준 — Twitter·Reddit·LinkedIn·Instagram 등 대부분 동일 방식.

## 번역 전략 (2트랙)
1. **Trillion 내부 콘텐츠**(피드·헤드라인·요약) = 서버에서 한국어로 번역해 보여줌. (이미 구현: 비공식 Google Translate + `translation_cache`. 향후 요약·핵심데이터로 확대 → 이탈 자체를 줄이는 게 진짜 해자.)
2. **외부 목적지 사이트** = 브라우저 자동번역에 위임. **직접 만들지 않는다.** 인앱 탭이 브라우저 엔진이라 자동 처리됨.

## 현재 상태
- **웹(현재)**: 외부 링크 전부 `target="_blank" rel="noopener noreferrer[ nofollow]"`로 새 브라우저 탭 오픈 → 브라우저 자동번역 처리됨. **추가 작업 없음 (이미 정상).**
- **앱(미래)**: 위 결정대로 SFSafariViewController / Chrome Custom Tabs 적용 시점에 반영. 난이도 낮음(표준 컴포넌트).

## 선택 개선 (나중, 옵션)
- **인앱 브라우저 감지**(카톡·네이버·인스타 웹뷰) → "외부 브라우저로 열기" 넛지. 자동번역이 안 되는 유일한 케이스라 이탈·불편 방지 효과. (웹·앱 공통)
- **원타임 힌트**: 외국 국가 탭 첫 방문 시 "외국 사이트는 브라우저 번역으로 통째 번역돼요" 가벼운 안내.

## 한 줄 요약
**번역 기능은 만들지 않는다.** Trillion 내부 콘텐츠만 번역해 보여주고, 외부 사이트는 인앱 커스텀탭(브라우저 엔진)이 자동번역까지 알아서 하게 둔다. 앱에서 딱 하나 — 생 웹뷰 대신 커스텀탭/SafariVC로 열기.
