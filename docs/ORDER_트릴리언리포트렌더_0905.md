# ORDER — Trillion 종목 페이지 리포트 렌더 (2026-09-05)

배관의 "읽는 쪽". 종목 페이지가 channel_reports 테이블을 읽어, 앞서
만든 "리포트 준비 중" 자리에 그 종목의 리포트를 **시간순 레이어**로
표시한다. **디자인은 최소** — 작동 검증이 목적이고, 예쁘게 다듬는 것은
이후 리브랜딩 STEP에서 한다(트래픽 0이라 중간 상태 노출 무방).

## 확정 방향 (사용자 확정)
- 지금은 배관 우선 · 디자인 최소. 리브랜딩(브랜드명·디자인·도메인
  전면 교체)은 배관이 작동한 뒤 별도로 진행.
- 표시: 종목 페이지에서 `symbol = X ORDER BY report_date DESC`로 그
  종목 리포트를 최신이 위로 쌓기. 여러 리포트가 레이어로 누적.
- KR만. US는 이후.

## STEP 1 — 읽기 API + 렌더 (한 STEP에 실행, 단 아래 순서로)

### 1-A. 조회 경로
- channel_reports를 symbol로 조회하는 서버 경로 추가(기존 /api 라우트
  컨벤션 따르기, 또는 서버 컴포넌트에서 직접 supabase select — 이 저장소
  관례에 맞는 쪽 판단해서). fetchAllRows 같은 전체조회 유틸이 필요한
  규모는 아니지만(한 종목 리포트 수십 건 이하) PostgREST 1000행 캡·
  .order() 규칙은 지킬 것.
- 미매칭(symbol IS NULL) 행은 애초에 안 뽑힘(WHERE symbol=X) — 설계대로.

### 1-B. 렌더 (디자인 최소)
- 종목 페이지의 "리포트 준비 중" 플레이스홀더 자리에 리포트 레이어를
  넣는다. 리포트 1건 = 카드 하나, 최신이 위.
- 카드에 표시할 필드(landing.json 대로): report_date · broker ·
  verdict(상향/유지/하향) · target_price · current_price · upside ·
  reasons(title+detail 목록) · earnings_summary. broker_average는 값
  있을 때만.
- 최소 스타일: 기존 Trillion 다크 토큰(미드나잇+민트) 재사용, 새 디자인
  하지 말 것. 카드 구분·판정 색(상향/하향) 정도만. 공들이지 않는다.
- 리포트 0건이면 "아직 리포트 없음" 빈 상태.
- verdict·수치는 원문 문자열 그대로 출력(파싱·재계산 금지 — 1군).

### 1-C. 작동 검증용 테스트 행
- channel_reports에 **테스트 행 2~3건**을 임시로 INSERT(실제 종목코드
  예: 롯데지주 004990, 팬오션 등 — kr_stock_snapshot에 있는 코드로).
  landing.json 실물 값(앞선 조사의 팬오션 등)을 그대로 써서.
- 라이브 종목 페이지(/stock/004990 등)에서 리포트가 시간순으로 뜨는지
  육안 확인 → **스크린샷 대신 렌더된 필드를 보고에 텍스트로 나열**.
- 검증 끝나면 **테스트 행 삭제**(DELETE) — 실제 데이터만 남게. 삭제까지
  이 STEP에서 완료하고, 삭제 확인도 보고.

## 하지 말 것
- 홈(오늘) 피드는 이번 범위 아님 — 종목 페이지만.
- 채널 push(쓰기)는 다음 STEP.
- 새 디자인·리브랜딩 요소 금지(최소 스타일만).
- 모델 크론·계산 변경 금지.
- 테스트 행을 남기지 말 것(검증 후 삭제 필수).
