## 결함 1 — 🔴 이름이 실제와 다르다

```ts
meta: { key: "valuation", nameEn: "Value (E/P · B/M)", ... }
const vState = peVal == null ? "na" : verdictState("valuation", peVal, cuts) ?? "na";
```

이름은 **E/P와 B/M 두 축**이라고 말한다. 실제 판정(`vState`)은 **`peVal` 하나**로만 난다. `pb`는 `detail: { per, pbr }`에 숫자로 실릴 뿐 **판정 기여 0%**이고, `value`(분포·스크리닝용)에도 `peVal`만 들어간다.

🔴 **사용자는 이름을 보고 두 축으로 봤다고 읽는다.** 이건 「무엇으로 판정하는지 밝힌다」는 원칙 위반이며, 820이 기술 렌즈에서 잡아낸 *"한 카드 안에 판정 기준이 두 개"*와 **같은 유형**이다(그때는 근거줄 vs 판정축, 이번엔 이름 vs 판정축).

---

## 결함 2 — 🔴 우리가 계산한 값이 아니다

```ts
// lensCompute.ts:145
if (pe != null) peBasis = "ttm"; // 야후 trailingPE = 최근 4분기(TTM)
// lensCompute.ts:241
if (pe == null) { pe = perFrom(mc, lr?.netIncome); if (pe != null) peBasis = "annual"; }
```

**1순위 = 야후 `trailingPE`.** 우리가 원자료(SEC/DART)에서 계산하는 건 **야후가 값을 안 줄 때의 폴백뿐**이다.

🔴 `BRAND_IDENTITY` 직시 기둥 — *"정직한 1차 재료. **남의 말이 아니라 직접 보고.**"* 정면 위반이다.
🔴 그리고 **야후가 어떤 이익을 썼는지(계속영업/희석/조정) 우리는 모른다.** 검산이 불가능하다.

🔑 역DCF는 SEC companyfacts 원자료에서 직접 계산한다. **밸류 렌즈는 그렇지 않다.** 같은 플랫폼 안에서 기준이 다르다.

---

## 결함 3 — 🔴 다른 잣대를 한 통에 섞는다

같은 시장 안에서 어떤 종목은 **TTM PER**, 어떤 종목은 **직전 연간 PER**로 값이 매겨진다. `peBasis`로 화면 문구를 분기(809)하긴 하지만 —

🔴 **`lens_cuts` 분포 컷을 만들 때 두 기준이 한 통에 들어간다.** p30/p70 컷이 서로 다른 잣대로 잰 값들의 분포에서 나온다. 「싸다/보통/비싸다」 판정의 경계선 자체가 오염돼 있다.

**이건 833이 US 유니버스에서 잡은 것과 같은 부류다** — *"편향 표본으로 판정 컷을 만드는 게 진짜 피해"*.

---

## 결함 4 — 🔴 적자기업이 통째로 빠진다

```ts
const peVal = pe == null || pe <= 0 ? null : pe;
value: round(peVal), // 적자 음수 PER은 na라 분포 오염 금지
```

적자면 `na`. 분포에서도 제외.

🔴 **이 렌즈는 적자기업에게 아무 말도 못 한다.** 그리고 그 처리가 「E/P」라는 이름과 모순된다 — **학술 E/P는 음수를 연속적으로 다룬다.** PER은 적자에서 발산하니 못 다루는 것이고, 즉 우리는 **E/P가 아니라 PER을 쓰면서 이름만 E/P**다.

822가 na 사유를 셋(우선주·적자·결측)으로 나눈 건 잘한 일이지만, **사유를 나눈 것이지 다룰 수 있게 된 건 아니다.**

---

## 결함 5 — 🔴 알면서 안 고쳤다

코드 주석(`lenses.ts:237`)이 스스로 적고 있다:

> *"절대 임계값의 verdict는 검증 밖(**상대·섹터내 비교가 맞음**)"*

그런데 실제 컷은:

```ts
// lensCuts.ts:13
export const CUT_LENSES = ["momentum", "lowvol", "valuation", "quality", "assetgrowth"];
// 컷 단위 = (market, lens_key) — 섹터 구분 없음
```

🔴 **시장(KR/US) 단위 분포 하나로 전 종목을 판정한다. 섹터 구분이 0이다.** 반도체·은행·유틸리티가 같은 PER 분포에서 「싸다/비싸다」로 갈린다.

🔑 **PER은 업종 간 비교가 성립하지 않는 대표적 지표다.** 이건 데이터 결함이 아니라 **설계가 자기 주석과 어긋난 상태**이고, 그 사실이 코드에 적혀 있는데도 남아 있다.

---

## 결함 6 — 🟡 B/M은 계산조차 안 한다

`d.pb`를 야후에서 받아 `detail.pbr`에 표시만 한다. 우리 계산 없음, 판정 기여 없음, 분포 없음.

## 🟢 잘 돼 있는 것 — 정직성 표기

| 항목 | 상태 |
|---|---|
| 등급 | `weakSignal`(약한 신호) · `gradeTier: "partial"` — **부풀리지 않음** |
| 주석 | *"정설이나 **우리 표본선 약함**"* |
| 라벨 | *"저평가/고평가" 대신 "낮음/보통/높음"* — 🔑 가치 판단을 피하고 사실만 |
| na 사유 | 우선주/적자/결측 3분기(822) |
| 컷 출처 | `cutSource`로 노출 |

🔑 **"하드코딩급 날조"라는 표현은 정직성 표기에는 해당하지 않는다.** 화면은 약하다고 말하고 있다. 문제는 **무엇으로 판정하는지가 이름과 다르고, 그 값을 우리가 만들지 않았고, 잣대가 섞여 있다**는 것이다.

## 🔴 그래서 밸류 렌즈를 "제대로" 만든다면 필요한 것

| # | 해야 할 일 |
|---|---|
| 1 | PER을 **SEC/DART 원자료에서 직접 계산**(야후 의존 제거) — 어느 이익인지 고정·공개 |
| 2 | 잣대 **하나로 통일**(TTM이면 전부 TTM) — 못 하면 두 분포를 분리 |
| 3 | 이름을 실제에 맞추거나(**"PER"**), B/M을 실제로 판정에 넣거나 — 🔴 **둘 중 하나** |

| 5 | **섹터 내 컷**으로 바꾸거나, 시장 전체 컷임을 화면에 명시 |

🔴 **미측정**: 위 6건을 고쳤을 때 KR·US 실제 커버리지가 얼마나 나오는지는 재보지 않았다.

## 2-4. 🔑 그래서 답

**"제대로 실행이 안 된 거야?"** →

- **지금은 됩니다.** 934·935·936은 성공·실패·미측정·불변항목까지 전부 적혀 있습니다.
- 🔴 **한 번 21개 STEP이 뚫렸고**(808~828), catch-up으로 메우면서 **개별 기록이 범위로 압축됐습니다.**
- 🔴 **837 하나는 지금도 공백입니다** — 만들어놓고 실행 안 한 명령서이고, 그 자리가 역DCF 전환 지점입니다.
- 🔴 **"실패한 것"을 별도로 모은 목록은 없습니다.** 플레이북이 문제·원인·해결을 담지만 *"이 STEP은 실패했다"*를 한눈에 보는 표는 없습니다. **CHANGELOG를 847KB 읽어야 압니다.**
