- 🔴 **다르면** → **멈추고 보고.** 어느 쪽이 최신인지 판정 필요
- 🔴 **main에 없는 untracked 파일**(예: `docs/probe_1055_invariance.json`)은 **지우지 않는다.** 그대로 둔다

## 2. 할 일

### 2-0. 🔴 손실 점검 — **이것부터. 하나라도 걸리면 멈추고 보고**
㉠ `git log --oneline main..worktree-step1055` → **0줄이어야 한다**
㉡ worktree에서 `git status --porcelain` → **0줄이어야 한다**
㉢ 메인 폴더 `git status --porcelain` 전량 나열 + untracked 각각을 `origin/main`과 diff (⓪-4④)
㉣ `gh pr view 1` → 상태 확인. **open이면 멈춘다**
🔴 **네 결과를 산출물에 원문 그대로 싣는다.**

### 2-1. 메인 폴더를 `main` 최신으로
`git fetch origin` → `git status` 확인 → **㉢에서 「같음」으로 판명된 untracked만 제거** → `git pull --ff-only origin main`.
🔴 **`--ff-only`를 쓴다.** 머지 커밋을 만들지 않는다. ff가 안 되면 **멈추고 보고**(메인 폴더에 로컬 커밋이 있다는 뜻).
🔴 **`reset --hard`·`clean` 쓰지 않는다.**
확인: `git log --oneline -1`이 **8d04143 이상**이고 `docs/model_list_30_9.html`이 **존재**할 것.

### 2-2. worktree 처분 — 🔴 §2-0 전부 통과한 경우에만
- `git worktree list`로 현재 목록 기록
- **제거**: `git worktree remove .claude/worktrees/step1055`(또는 `--force` 없이). 실패하면 **강제하지 말고 사유를 보고**
- **로컬 브랜치 삭제**: `git branch -d worktree-step1055` — 🔴 **`-d`(안전 삭제)만 쓴다. `-D` 금지.** `-d`가 거부하면 **머지 안 된 커밋이 있다는 뜻이므로 멈추고 보고**
- 🔴 **원격 브랜치는 지우지 않는다**(별도 판정)
- 🔴 **PR #1은 건드리지 않는다**(닫기·머지 모두 판정 사항)

### 2-3. 🔴 왜 worktree가 생겼는지 기록
`.claude/` 설정·`CLAUDE.md`·STEP1055 명령서를 확인해 **worktree가 어디서 지시됐는지** 찾는다.
🔴 **찾으면** → 그 지시를 인용하고, 브랜치 규약과의 충돌을 §2-4에 반영.
🔴 **못 찾으면** → *"출처 미확인 — 도구가 자동 생성했을 가능성"*으로 적는다. **추측을 사실로 쓰지 않는다.**

### 2-4. 🔴 브랜치 규약에 worktree 조항 추가
`docs/COMMIT_GATES.md`의 브랜치 규약에 **한 줄 신설**:
> **작업 폴더도 하나다.** STEP은 **저장소 루트에서 직접** 작업한다. `git worktree`를 만들지 않는다. 브랜치를 안 만드는 것과 같은 이유다 — **작업 폴더가 둘이면 사용자가 보는 폴더와 실제 작업 폴더가 갈리고, 그때 어느 쪽이 진짜인지 알 수 없게 된다**(2026-08-18 실측: STEP1055~1069 15개가 worktree에서 실행돼 메인 폴더가 사흘 뒤처짐).

🔴 **기존 규약 문장을 지우지 않는다.** 아래에 덧붙인다.

### 2-5. 상태 한 장 — 앞으로 안 헷갈리게
`docs/STATE.md`(현황 정본)에 **「어디를 보면 되는가」** 절을 추가한다:
