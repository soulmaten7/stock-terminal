# STEP 1007 — 로컬에서 재현이 안 되는 두 실패를 프로덕션에서 직접 관측한다 (계측 배선 · 값 불변)

## 0. 이 STEP이 왜 이 모양인가

STEP 1006이 낸 결론은 사실상 하나다. **두 실패 모두 로컬에서 재현되지 않는다.**

| | 프로덕션 | 로컬(1006) |
|---|---|---|
| 야후 `quote()` marketCap | 373건 **전부 결측** | 390건 중 **304건 정상**(77.9%) · HD·LOW·TGT·MU·CRM 완전 데이터 |
| `revdcf` finally 블록 | `us_sector_relative` 3일째 0행 | 6구간 누적 **5.4초** · 예외 0 · 잔여예산(30s)의 18% |

🔴 **이건 987에서 이미 한 번 나왔던 패턴이다**(로컬에서 349건 전부 marketCap 정상 수신). 즉 **로컬 성공 / 프로덕션 실패**가 서로 다른 두 STEP에서 **독립적으로 두 번** 관측됐다.

그리고 프로덕션 쪽에는 반대 방향의 강한 제약이 있다:
- `us_market_cap`의 `as_of='2026-07-30'` 296건이 **14일 연속 같은 심볼로 고정**돼 있다 → 실패 종목은 매일 랜덤이 아니라 **고정**이다.
- 그런데 그 고정된 종목이 로컬에서는 성공한다.

**「종목 고유 속성」 ∧ 「환경 의존」** 의 교집합만 남는다. 로컬에서 몇 번을 더 재도 이 교집합은 안 좁혀진다.
🔴 **따라서 이번 STEP은 로컬 프로브를 하지 않는다. 프로덕션에서만 얻을 수 있는 값을 심는다.**

🔴 그리고 이번에도 **원인을 고치지 않는다.** 취득 경로 교체(`chart()` 폴백)는 매력적으로 보이지만,
`chart()`는 **가격만 주고 주식수를 안 준다** → 시총을 재구성해야 하고 → 그 373건만 `us_fundamentals.shares`(FY 가중평균 희석) 계열이 되어
나머지 5,601건(야후 계열)과 **계산기준이 섞인다.** 08-13 실측으로 그 위험은 이미 확인됐다(<0.3B 구간 절대차 중앙값 11.8% · p90 223%).
🔴 **원인 확정 전에 취득 경로를 바꾸지 않는다.**

## 1. 1006에서 확정된 것 / 확정 안 된 것 (그대로 인용)

**확정**
- 야후는 응답을 준다: `noResponse 0` · `failedChunks 0/60` · `retryFailReasons {}` · `countHit/timeHit false`
- 개별 재시도 373건 전부 정상 응답인데 marketCap 없음(`retryNoCapField 373` · `recovered 0`)
- 재구성으로는 컷을 못 연다: `reconstructable 17` → `wouldBeCoverage 94.04%`(97% 게이트에 3.24pp 부족)
- `quoteSummary()`는 `quote()` 대비 **1건**만 추가 회복 → 별도 취득 경로가 못 된다
- 진짜 이중결측 85건(21.8%)은 우선주·레버리지/인버스 ETN·GV/KVAC/PSTV — **987과 정확히 재현**(이건 종목 속성으로 설명되는 부분)
- P2 6구간 누적 5.4초 · 예외 0

**확정 안 됨**
- exchange 분포(target NYSE American+Arca+Cboe 14.4% vs control 4.4%)는 라이선스 가설과 **방향만** 일치. 양쪽 다 NYQ가 최대 비중이라 **부분 신호일 뿐 설명이 안 된다.**
- 2026-07-30 그 시점 프로덕션 상태의 직접 증거 — **없다. 앞으로도 못 얻는다.**(소급 불가)
- P2 가설 ⓐ(예산 초과)·ⓑ(내부 예외) 어느 쪽도 확정·기각 안 됨. 로컬↔Vercel 차이 3가지가 남아 있다: SEC 워커 루프 직후 리소스 상태 · 콜드스타트 · 네트워크 RTT

## 2. 할 일 — 프로덕션 계측 2개

### W1. `revdcf` 크론에 `recordHeartbeat` 추가 (P2 확정)

🔴 **이게 없어서 3일째 어디서 죽는지 모른다.** `cron_heartbeats`에 등록된 job은 `lens-scores`·`kr-lens-scores`·`email-brief`·`jp-disclosures` 4개뿐이고 `revdcf`는 없다.

`app/api/cron/revdcf/route.ts`:
- `finally` 블록의 **각 구간 앞뒤에 `Date.now()` 경계를 찍는다**. 1006 P2가 로컬에서 쟀던 6구간과 **같은 이름·같은 경계**로 맞춘다(로컬↔프로덕션 직접 대조가 목적이다).
- 응답 JSON에 이미 있는 필드(`processed`·`finished`·`elapsedMs`·`valuationSaved`·`sectorRelativeSaved`·`sectorWideAdded`·`sectorWideError`)를 **그대로** heartbeat note에 싣는다.
- 추가로 싣는다: `loopMs`(SEC 워커 루프) · `budgetExhausted`(= `Date.now()-t0 >= BUDGET_MS`가 루프 종료 사유였는지) · `finallyMs` 6구간 · `finallyTotalMs` · `routeMs`
- 🔴 `computeAndSaveSectorRelative`를 **try/catch로 감싸 예외를 삼키지 말고 기록**한다: `sectorRelativeError`(message + stack 앞 500자). 🔴 **삼킨 뒤 계속 진행이 아니라, 기록하고 다시 던진다** — 833의 "조용히 안 버린다" 원칙.
- 🔴 `recordHeartbeat` 자체는 **try/catch로 격리**해 계측 실패가 크론을 죽이지 않게 한다(917 §2와 같은 방식).

🔴 **값 불변 조건**: `BUDGET_MS`(270_000) · `maxDuration`(300) · 워커 수(6) · 계산 로직 · upsert 대상 — **하나도 바꾸지 않는다.**
이번 STEP은 **어디서 잘리는지 보는 것**이지 고치는 게 아니다. `BUDGET_MS`를 내릴지는 이 계측값을 보고 STEP 1008에서 정한다.

### W2. 야후 진단 엔드포인트 `app/api/diag/yahoo/route.ts` (P1 확정)

🔴 **크론이 아니다.** Vercel 크론 9개 슬롯을 쓰지 않는다. `vercel.json`을 건드리지 않는다(app router가 자동 인식).
🔴 인증: `Authorization: Bearer ${CRON_SECRET}` 필수. 없으면 401. 🔴 **키 VALUE를 코드나 문서에 타이핑하지 않는다.**
🔴 **DB에 한 행도 쓰지 않는다.** 결과는 응답 JSON으로만 돌려준다.

동작:
- 쿼리파라미터 `?symbols=A,B,C`(최대 50개, 미지정 시 아래 고정 12종목)
- 고정 기본 목록 — 1006에서 **로컬은 완전 데이터**였던 대형주 5 + 대조군 7:
  `HD,LOW,TGT,MU,CRM` (로컬 성공 · 프로덕션 실패) / `AAPL,MSFT,NVDA` (양쪽 성공) / `GV,KVAC,PSTV,USA` (양쪽 실패 · 이중결측군)
- 각 심볼에 `yf.quote()` 1회. 🔴 **동시성 1 · 호출 간 200ms.** 진단이 야후에 부담을 주면 안 된다.
- 돌려주는 것: 심볼별로 `marketCap`·`regularMarketPrice`·`sharesOutstanding`의 **존재 여부(값 아님)**, `quoteType`·`exchange`·`fullExchangeName`·`marketState`, 그리고 **수신된 전체 필드명 배열**
- 응답 상단에 실행 환경: `process.env.VERCEL_REGION` · `VERCEL_ENV` · 응답 시각(UTC)

🔴 **이 엔드포인트의 목적은 단 하나다**: `HD`가 로컬에서는 marketCap을 주고 프로덕션에서는 안 주는 것이 **사실인지 확인**하는 것.
- 프로덕션에서 HD·LOW·TGT·MU·CRM이 **marketCap 결측**으로 나오면 → **환경 차이 확정.** 그다음 축은 IP/리전이다.
- 프로덕션에서도 **정상 수신**되면 → 🔴 **환경 가설이 무너진다.** 그러면 축은 `lens-scores` 크론 안의 **배치 호출 방식**(60청크 × 동시성 6)으로 옮겨간다. 그 경우를 그대로 적을 것.
- 🔴 **어느 쪽이 나오든 원인을 단정하지 말 것.** 다음 축이 무엇인지만 적는다.
