### W2. 새 게이트 산식 — 🔴 관측 필드로만
`lib/lensPrecompute.ts`의 `capGateDecision`에 **반환 필드를 추가**한다. 🔴 **기존 4개 필드의 계산은 불변.**

새 산식(제안값 — 🔴 상수는 코드 상단에 명명 상수로, 근거 주석과 함께):
```
ABS_FLOOR   = 0.85   // 절대 하한. 서서히 나빠지는 걸 막는다
DROP_LIMIT  = 0.03   // 전일 대비 낙폭 상한(3%p). 832형 사고(98.6%→~0%)를 잡는다
newCoverageOk = freshCoverage >= ABS_FLOOR
             && (priorCoverage == null || freshCoverage >= priorCoverage - DROP_LIMIT)
newCutGateOk  = newCoverageOk && compositionOk    // compositionOk는 불변
```
- **`priorCoverage` 출처**: `us_coverage_history`의 **직전 `as_of`**(오늘 것 제외) · 없으면 `cron_heartbeats.job='lens-scores'` note의 `freshCoverage`로 폴백 · 둘 다 없으면 `null`(부트스트랩 = 절대 하한만)
- 🔴 **부트스트랩 경로를 반드시 명시적으로 구현**한다. 첫 실행엔 이력이 없다
- 🔴 반환/heartbeat에 싣는다: `newCoverageOk` · `newCutGateOk` · `priorCoverage` · `priorSource`(history/heartbeat/none) · `coverageDrop`
- 🔴 **`cutGateOk`(실제 판정)는 현행 산식 그대로 반환한다.** 새 값은 옆에 나란히 기록만

🔴 **불변 증명**: 833의 값 잠금 테스트가 **수정 없이 그대로 통과**해야 한다. 🔴 테스트를 고쳐서 통과시키면 실패다.

### W3. 프루닝 가상 영향 — 🔴 계산만, 실행 안 함
