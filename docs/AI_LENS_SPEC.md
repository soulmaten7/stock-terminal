# 운종 · AI 렌즈 해설 — 설계 스펙 (완성본, 빌드 보류·검토용)

> ⚠️ **[이력·폐기]** 구 정체성("네 기둥"·"안 속게") 기반 설계 스펙 — 현행 정체성 권위 = `docs/BRAND_IDENTITY.md` (3기둥 무기·직시·자립 · "종목을 보는 눈을, 누구에게나"). 렌즈 개념은 현행 TR-AI 렌즈(빌드됨)로 계승 — 엔진 실제 문서는 `docs/LENS_DEV_PLAYBOOK.md`.

> **이 문서의 목적**: AI 해설 기능을 "넣을지 말지" 나중에 결정하기 위해 **설계를 끝까지 완성**해 둔 것. 빌드는 아직 안 함.
> **한 줄**: 같은 종목/상품을 **여러 '렌즈'(가치·모멘텀…)로 데이터에 근거해 해설**해서, 이용자가 "정답"이 아니라 **읽는 법**을 배우게 한다. 추천·예측·단타 신호 아님.

---

## 0. 왜 (정체성 정합)

- 운종의 네 기둥 중 **'가르친다(읽는 법)'**의 실현. "물고기를 주는 게 아니라 낚는 법."
- 안 속게 / 스스로 판단: 단일 "사라/팔아"가 아니라, **같은 숫자를 관점마다 다르게 읽는 법**을 보여줘 이용자가 직접 판단하게.
- 차별점: 리딩방·증권사 리포트는 "결론(픽)"을 줌. 운종은 **결론을 안 주고 '읽는 틀'을 줌.** 그래서 안 현혹됨.

## 1. 절대 가드레일 (제일 중요 — 이게 무너지면 운종이 리딩방이 됨)

해설은 **해설**이지, 추천·예측·신호가 **절대 아니다.**

- ❌ 금지: "사세요/파세요", "지금이 기회", 목표주가, "단타 들어가라", "급등 임박", 매수/매도 타이밍, 미래 가격 예측.
- ✅ 허용: 과거·현재 **데이터의 의미 해설**, 관점별 **읽는 틀** 설명, **양면**(긍정/위험) 동시 제시, "이 지표는 X를 뜻한다"는 교육.
- **모멘텀 렌즈의 함정**: '모멘텀'이라고 단타 신호를 주면 안 됨. 모멘텀 렌즈 = "최근 추세·수급이 어떤 상태인지 **해설**" + "추세 추종은 고점매수 위험" 같은 **교육적 경고**로 끝남. 절대 "지금 타라" 아님.
- **모든 해설 끝에**: "이건 추천이 아니라 데이터 해설입니다. 투자 판단·책임은 본인에게 있어요." (면책)
- **균형 강제**: 한 렌즈에서 긍정만/부정만 X → 항상 "이렇게 볼 수도, 저런 위험도" 양면.
- **출처 명시**: 모든 수치는 출처(DART·KRX·KIS·yahoo) 달기 → 환각 시 검증 가능 + 신뢰.

> 프롬프트·UI·캐시 어디서든 이 가드레일이 1순위. (기존 `/api/ai-analysis` 시스템 프롬프트에 "투자 추천은 하지 않습니다"가 이미 있음 — 더 강화.)

## 2. 현재 자산 (백지 아님)

이미 있는 것:
- **`/api/ai-analysis`** (route.ts): `POST` = OpenAI **gpt-4o-mini**로 타입별 해설 생성 → Supabase **`ai_analysis` 테이블** 캐시(7일 만료). `GET` = 캐시 조회. env `OPENAI_API_KEY`.
- **타입 5종**: `value`(가치) · `technical`(기술적) · `quant`(모멘텀·밸류·퀄리티) · `dividend`(배당) · `supply`(수급). 시스템 프롬프트에 "객관적 데이터 정리, 추천 안 함, 3~5문장" 이미 있음.
- **데이터 소스(해설 근거가 될 것)**: DART 재무(`/api/stocks/earnings`) · 수급(`/api/kis/investor`) · 업종(`/api/kis/sector`) · 기간 수익률(STEP 243~246 `*-performance`) · 시총(KRX) · 차트.
- **`StockInsightsTab`**: 종목 상세에서 재무·수급·업종 **원시 표**만 보여줌 — **AI 텍스트는 아직 미연결**.

> 결론: **생성 엔진·캐시·가드레일 뼈대는 있음.** 할 일 = ① 렌즈로 재정렬 ② 입력 데이터 번들 정의 ③ UI 연결 ④ 가드레일·교육 톤 강화.

## 3. 렌즈 (관점) — 같은 데이터, 다른 읽기

| 렌즈 | 무엇을 보나 | 근거 데이터 | 기존 타입 매핑 |
|------|------------|------------|---------------|
| **가치** | 기업 본질·싼가/비싼가·체력 | PER·PBR·ROE·부채비율·마진(DART), 시총, 동종업계 | `value` |
| **모멘텀** | 추세·수급 흐름(해설, 신호 X) | 기간 수익률(1주~1년), 거래량, 외국인·기관 수급, 업종 | `quant`+`technical`+`supply` 통합 |
| **배당** (배당주만) | 배당 수익률·안정성·성장 | 배당 이력·배당성향 | `dividend` |

- 핵심 UX: **두 렌즈를 나란히** 보여줌 → "같은 종목도 가치로 보면 비싸 보이고, 모멘텀으로 보면 강해 보인다" → **정답 없음 = 스스로 판단**(안 현혹).
- 각 렌즈 첫 줄에 **렌즈 정의 한 줄**(교육): 예) "가치 관점 = 기업이 버는 돈 대비 주가가 싼지 보는 틀."
- 상품(ETF·리츠)은 렌즈가 다름: ETF/리츠는 '구성·수수료·추적오차·기간 성과' 중심(별도 렌즈셋 — v2).

## 4. 출력 형식

- 렌즈당 **3~5문장**(기존 유지), 구조: ① 렌즈 정의 한 줄 → ② 데이터 해설(수치+출처) → ③ 양면(이렇게 볼 수도/이 위험도) → ④ 면책 한 줄.
- 톤: 차분·중립·교육적. 단정 X("~로 보인다/~할 수 있다"). 감탄·재촉 금지.
- 길이: 짧게. 길면 안 읽음 + 단정 위험 ↑.

**예시 (삼성전자, 가상 데이터 — 톤·구조 참고용):**

> **가치 렌즈** · 기업이 버는 돈 대비 주가가 싼지 보는 틀
> PER 12배·PBR 1.3배·ROE 9%(출처 DART)로, 반도체 동종 평균(PER 15배)보다 낮은 편이에요. 가치 관점에선 "이익 대비 저평가"로 읽을 수 있지만, ROE가 동종 상위권은 아니라 '싼 데는 이유가 있다'고 볼 여지도 있어요. 부채비율 40%로 체력은 안정적. — *데이터 해설이며 추천이 아닙니다.*

> **모멘텀 렌즈** · 최근 추세·수급 흐름을 보는 틀
> 최근 3개월 +18%, 거래량은 평균의 1.6배, 외국인 5일 연속 순매수(출처 KRX·KIS)로 단기 추세는 강한 편이에요. 모멘텀 관점에선 "흐름이 살아있다"로 읽히지만, 추세 추종은 고점 매수 위험이 늘 따르고 모멘텀은 빠르게 꺾일 수 있어요. — *현재 흐름의 해설이며 매매 신호가 아닙니다.*

## 5. 노출 위치 · 트리거

- **1순위: 종목 상세 페이지**(`/stock/{symbol}`) — `StockInsightsTab` 안 또는 새 'AI 렌즈' 섹션. 데이터를 본 맥락에서 해설.
- **트리거: on-demand** — "AI 렌즈 해설 보기" 버튼 클릭 시 생성/조회(비용·남용 방지). 자동 생성 X.
- **캐시**: `ai_analysis` 테이블(이미 있음), 만료 후 재생성. 같은 종목 재방문 = 캐시 즉시.
- **미리보기 패널(hover)**: v1 제외(transient·비용). 상세 페이지에서만. (추후 "한 줄 요약"만 미리보기에 캐시값으로 노출 검토.)
- **상품 리스트/홈**: 렌즈 해설은 안 띄움(목록은 숫자만). 클릭해 들어가야 해설 — '현혹 안 함' 원칙.

## 6. 기술 설계

- **모델**: 기존 gpt-4o-mini 유지(저비용·충분). temperature 0.3(사실 위주). max_tokens ~400/렌즈.
- **Grounding(환각 방지 핵심)**: 프롬프트에 **앱이 가진 실데이터만** JSON으로 주입(DART 재무·수급·기간수익률·시총). "주어진 데이터 밖 수치는 만들지 말 것" 명시. 모르는 건 "데이터 없음".
- **입력 번들 API**(신규 제안): `/api/ai-analysis`에 넘길 데이터를 한 번에 모으는 `buildAnalysisData(symbol)` — earnings+investor+performance+marketcap 취합.
- **캐시·비용**: on-demand + 7일 캐시라 호출 적음. 렌즈 2개 × gpt-4o-mini ≈ 매우 저렴. 남용 방지 rate-limit(IP/유저).
- **실패 처리**: API 키 없음/실패 → "해설 일시 불가, 데이터 표는 그대로" (표는 항상 보임). AI는 **부가**, 데이터가 본체.
- **env**: `OPENAI_API_KEY`(.env.local, 커밋 금지).

## 7. MVP vs 풀 스코프

- **MVP (v1)**: 종목 상세에서 **가치·모멘텀 2개 렌즈** on-demand 버튼 + 캐시 + 가드레일·면책. 국내 주식부터(재무·수급 데이터 풍부).
- **v2**: 배당 렌즈, 미국 주식, 상품(ETF·리츠) 렌즈셋(구성·수수료·추적오차), 미리보기 한 줄 요약.
- **v3**: 렌즈 비교 뷰("두 관점 충돌 지점" 하이라이트), 업종/동종 비교 해설.

## 8. 리스크 · 미결정 · 면책

- **리스크**: ① 환각(→ grounding+출처로 방지) ② 추천처럼 읽힘(→ 가드레일·면책·양면 강제) ③ 비용(→ on-demand·캐시) ④ 책임소재(→ 면책 배너, "정보 제공·자문 아님").
- **미결정(검토 시 정할 것)**:
  - (a) 렌즈를 '나란히 2개' vs '탭 전환'? → 추천: 나란히(정답 없음 강조).
  - (b) 모멘텀 렌즈를 아예 뺄지?(단타 오독 위험 최소화) → 추천: 넣되 가드레일 강하게(교육·경고 동반).
  - (c) gpt-4o-mini vs 다른 모델 → 추천: 유지(비용).
  - (d) 면책 수위·법무 검토 필요 여부.
- **법적**: 유사투자자문/투자자문업 경계 — "특정 종목 매매 권유"로 안 읽히게(렌즈=일반적 분석틀 교육). 면책 필수.

## 9. 빌드 결정 시 STEP 분해 (greenlight 되면)

1. **STEP A** — `buildAnalysisData(symbol)` + `/api/ai-analysis` 렌즈(가치·모멘텀) 프롬프트 강화(가드레일·교육 톤·출처·면책).
2. **STEP B** — `ai_analysis` 테이블 확인/마이그(있으면 재사용). 렌즈 키 정리(value/momentum).
3. **STEP C** — 종목 상세 'AI 렌즈 해설' 섹션 UI(on-demand 버튼 + 2렌즈 나란히 + 면책 배너 + 로딩/실패).
4. **STEP D** — rate-limit·캐시 검증, 가드레일 QA(추천처럼 읽히는지 샘플 점검).
5. (v2) 배당·상품 렌즈·미국 확장.

## 결론 (검토 포인트)

- **만들 가치**: 차별점의 마지막 기둥('가르친다') + 기존 인프라 재활용이라 비용·리스크 작음.
- **안 만들 이유가 된다면**: ① 추천 오독·법무 리스크가 무겁다고 판단 ② AI 텍스트보다 '숫자+링크아웃'이 더 운종답다고 판단.
- **이 문서로 "넣을지 말지"만 정하면 됨.** 넣기로 하면 위 STEP A~D로 바로 빌드.
