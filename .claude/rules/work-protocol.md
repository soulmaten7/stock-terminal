# 작업 절차 (work-protocol)

> CLAUDE.md 허브의 세부 규칙 파일 중 하나. 여기는 **"어떻게 작업하는가"**만 다룬다. 무엇을 참고하는지는 `docs-map.md`, 배포 안전장치는 `deploy-gates.md`, 실수 기록은 `mistakes.md`.

## 1. 운영 체계 (2026-09-05 확정)

이 저장소는 **클로드 채팅(설계·명령서) + 클로드 코드(실행)**로 운영한다. "Cowork"라는 별도 주체는 없다 — 설계·명령서 대화와 실행이 같은 문서 규칙 아래 있다.

🔴 **EarthTicker 운영의 설계·명령서 대화는 한국 채널 세션(이 채팅)이 전담한다.**

- **설계(채팅)**: 무엇을 만들지 결정, `docs/ORDER_*.md` 작성, Supabase 마이그레이션 적용(MCP), 문서 갱신.
- **실행(클로드 코드)**: 명령어 실행, 파일 수정, 빌드/테스트, git commit/push, 배포 확인(게이트 8).

## 2. 명령서 형식

- **파일**: `docs/ORDER_{제목}.md` + 실행 한 줄. STEP 번호·`STEP_LEDGER.md`는 폐지(동결, `docs/STEP_LEDGER.md` 참조) — 이력은 **git 커밋 메시지**로 남긴다.
- **판단 기준**(파일 vs 인라인 채팅 지시): "이 명령어를 한 달 뒤에 다시 봐야 할 가치가 있나?" → Yes면 `docs/ORDER_*.md` 파일, No면 채팅 인라인.
- 다단계(여러 파일 수정·git 커밋 포함·아키텍처 변경)는 파일. 단순 1~2파일·디버깅·긴급 핫픽스는 인라인.

## 3. 작업 원칙

- **한 번에 하나의 작업만** — 멀티태스킹 금지.
- **근거 없는 숫자 만들기 금지** — `docs/STATE.md`·라이브 실측(DB 직접 조회)·git 로그에 없는 수치를 쓰지 않는다.
- **완전성 = 축소가 아니다** — 범위를 임의로 "나중/선택"으로 빼지 않는다. "하나씩"은 순서일 뿐 범위 축소가 아니다.
- **확정 전 실행물 금지** — 사용자가 명시 확정("ㅇㅋ" 등)하기 전에는 코드·DB·프로덕션에 영향을 주는 실행을 하지 않는다. "읽고 보고만"과 "확정 후 적용"을 단계로 분리해 지시받았으면 그 경계를 지킨다.
- **뜻이 갈릴 수 있는 낱말은 분석 전에 되묻는다** — 스스로 정의해서 진행하지 않는다.

## 4. 보고 형식 — ⓪줄

모든 조사·보고에는 **"⓪ 실제로 연 파일:줄 / 조회한 테이블"**을 먼저 적는다. 안 적으면 "안 열고 말했다"로 간주한다.

```
⓪ 실제로 연 것: <파일:줄 / Supabase 테이블·쿼리 / Bash 명령 — 무엇을 확인했는지>
(본문 — 결과)
못 한 것: <조사하지 못한 항목, 확인 안 된 가정 — 없으면 "없음">
```

🔴 **미측정을 남긴 채 "완료"를 선언하지 않는다.** 못 한 것은 목록으로 명시한다.

## 5. 좌표 의무

- 단정할 때는 `파일:줄` 또는 `테이블명`(Supabase)을 근거로 붙인다. 못 달면 **"내 추측"**이라고 명시한다.
- 기억이나 요약본이 아니라 **그 자리를 직접 열어서** 확인한 것만 근거로 쓴다.
